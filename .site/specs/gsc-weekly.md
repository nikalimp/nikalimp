# Еженедельный разбор Google Search Console — nikalimp.ru

Запускается задачей по расписанию каждое воскресенье в 12:34 (Asia/Bangkok). Данные за полчаса до этого выгружает GitHub Actions `GSC weekly` (`.github/workflows/gsc-weekly.yml` → `.site/scripts/gsc-report.mjs`) в `.site/specs/reports/gsc/YYYY-MM-DD.json`.

## 1. Данные
1. `git pull` в репозитории nikalimp/NikitOS.
2. Найди свежий JSON в `.site/specs/reports/gsc/` (сегодняшняя дата). Если его нет:
   - проверь последний запуск: `gh run list --workflow gsc-weekly.yml -L 3`;
   - если не было или упал — `gh workflow run gsc-weekly.yml`, дождись завершения циклом `until` и сделай `git pull`;
   - если упал с ошибкой доступа (нет секрета, `account not found`, ресурс не открыт) — не анализируй, а пришли Нику короткую инструкцию, что настроить (см. «Настройка» ниже), и закончи.
3. Возьми прошлую выгрузку (предыдущий JSON в той же папке) — для сравнения неделя к неделе.

## 2. Что разобрать
- **Динамика**: клики, показы, CTR, позиция за 28 дней против предыдущих 28 (`totals`), тренд по дням (`daily`), отличие от прошлой выгрузки.
- **Что хорошо индексируется и растёт**: разделы из `bySection` с высокой долей `withImpressions / urls`; страницы из `pages` с ростом показов и кликов. Что из этого масштабировать: похожие страницы, перелинковка, расширение темы.
- **Что не индексируется**: `coverage` и `inspections` — «Обнаружена, не проиндексирована», «Просканирована, но не проиндексирована», дубли и чужой canonical (`googleCanonical ≠ userCanonical`), ошибки загрузки и robots. Сгруппируй по разделам и причине, найди общий шаблон (например, тонкие страницы `/tools/compare/`, карточки стартапов).
- **Быстрые победы**:
  - запросы и страницы на позициях 4–15 с показами — доработать текст, title, H1 и перелинковку;
  - страницы с большими показами и CTR ниже ~2% — переписать title и description;
  - запросы без своей страницы (`pageQueries`: запрос ведёт на нерелевантную страницу) — новая статья, термин глоссария или раздел.
- **Потери**: `pagesLost` и страницы с падением показов больше 30% — что изменилось (git log по файлам страницы), что вернуть.
- **Карта сайта**: `sitemaps` — ошибки, предупреждения, отправлено/проиндексировано.
- **Устройства и страны** — только если есть аномалия.

Сверяйся с кодом сайта (`.site/src`, `Library/`) — рекомендации должны указывать конкретные файлы и страницы, а не общие советы. Не выдумывай цифры: все числа — из JSON.

## 3. Результат
1. Отчёт `.site/specs/reports/gsc/YYYY-MM-DD.md`:
   - 3–5 строк сводки с цифрами;
   - **чек-лист рекомендаций** — нумерованный, 5–12 пунктов, по убыванию эффекта. Каждый пункт: `- [ ] N. Что сделать — на каких страницах (адреса или шаблон) — почему (цифры из GSC) — ожидаемый эффект — объём (S/M/L)`.
2. Коммит отчёта в ветку `claude/gsc-YYYY-MM-DD` и PR (папка specs не выкладывается на сайт), слить после зелёной проверки.
3. Пришли Нику сообщение (SendUserMessage) со сводкой и чек-листом целиком и вопросом: «Какие пункты запускаем? Ответь номерами, например: 1, 3, 5». Ничего на сайте не меняй до ответа.
4. После ответа — сделай выбранные пункты по правилам сайта (CLAUDE.md, скилл web-dev: Главред и Типограф, `npm run check`), PR → проверка → слияние → выкладка, проверка на живом сайте. В отчёте отметь выполненные пункты `[x]`.

## Настройка (делает Ник один раз)
1. Google Cloud Console → тот же проект, где ключ PageSpeed → APIs & Services → включить **Google Search Console API**.
2. IAM → Service Accounts → создать аккаунт (например, `gsc-reader`) → Keys → Add key → JSON.
3. Search Console → ресурс nikalimp.ru → Настройки → Пользователи и разрешения → добавить почту сервисного аккаунта (`…@….iam.gserviceaccount.com`) с правами «Ограниченный доступ».
4. GitHub → nikalimp/NikitOS → Settings → Secrets and variables → Actions → New secret `GSC_SERVICE_ACCOUNT` — вставить содержимое JSON-файла целиком.
5. Actions → GSC weekly → Run workflow — проверить, что выгрузка проходит.
