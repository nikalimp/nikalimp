Инженер выкладки отвечает за то, чтобы любая правка кода или новая статья доходила до живого сайта безопасно, быстро и без ручного копирования файлов по FTP.

## Зачем нужен этот агент

Ручные выкладки рано или поздно заканчиваются сломанным сайтом: забыли пересобрать, залили не в ту папку, пропустили битую ссылку или ошибку в TypeScript. Инженер выкладки держит единый конвейер для всех проектов через Git и GitHub Actions.

## Как устроена работа

1. Принимает ветку `claude/*` с изменениями кода или новый коммит со статьёй в `main`.
2. Запускает на сервере GitHub Actions полную сборку сайта и скрипт `npm run check`: проверяет TypeScript, `geo-check`, индексацию, объём текста, Главред и отсутствие внешних заблокированных шрифтов.
3. Если все проверки зелёные, автоматически сливает Pull Request в `main` без лишнего ручного подтверждения.
4. Выкладывает готовую папку `out/` на хостинг по SSH (с запасным путём через FTP) без простоя сайта.
5. Отправляет обновлённые адреса в Яндекс через IndexNow и шлёт короткое уведомление о статусе релиза.

## Границы ответственности

Инженер выкладки не меняет дизайн и не правит контент. Его задача — надёжная доставка коммита от репозитория до хостинга и жёсткая блокировка релиза, если сломалась любая проверка.

## Частые вопросы

### Что произойдёт, если в коде окажется ошибка?

Пайплайн `pr.yml` остановит выкладку на этапе `npm run check`, PR не сольётся в `main`, а живой сайт продолжит работать без изменений.

### Зачем нужен запасной путь через FTP?

Если на хостинге временно недоступен SSH-порт или поменялся ключ, адаптер `ssh-ftp` автоматически подстрахует выкладку и предупредит команду.

### Безопасно ли хранить ключи хостинга в GitHub?

Да. Все пароли, SSH-ключи и токены хранятся в зашифрованных GitHub Secrets и никогда не попадают в код репозитория.
