# API модели

**English:** Model API
**Категория:** [[Глоссарий — AI и LLM]]
**URL:** nikalimp.ru/glossary/model-api

## Определение

API модели — это программный интерфейс, через который приложение отправляет запрос языковой модели и получает ответ, не используя чат на сайте сервиса. Разработчик отправляет текст по сети и получает сгенерированный результат в структурированном виде.

Обычно это HTTP-запрос в формате [[JSON]]: вы передаёте название модели, сообщения диалога и параметры, а в ответ приходит текст, число использованных токенов и служебные данные. Доступ выдаётся по секретному ключу, который нельзя хранить в открытом коде. Так устроены API у OpenAI, Anthropic, Google, Яндекса, Сбера и других поставщиков. Технически это частный случай [[REST API]].

Через API модель встраивают в сайты, боты, CRM, редакторы и автоматизации. Например, форма на сайте отправляет вопрос клиента модели с описанием услуг и возвращает ответ; бот в Telegram отвечает на вопросы по базе знаний; скрипт каждую ночь классифицирует обращения. Оплата чаще всего зависит от числа [[Токен|токенов]] во входе и выходе, поэтому длинные запросы и ответы стоят дороже. Конкретные тарифы меняются, смотрите их на сайте провайдера.

### Из чего состоит запрос
- Название модели и версия.
- Сообщения: системная инструкция, реплики пользователя и модели.
- Параметры: [[Температура|температура]], максимальная длина ответа, формат результата.
- Дополнительно: описания инструментов для [[Function calling|вызова функций]].

### Как начать пользоваться
1. Зарегистрируйтесь у провайдера и создайте ключ API.
2. Положите ключ в переменную окружения, а не в код, который попадёт в репозиторий.
3. Отправьте тестовый запрос из документации и посмотрите ответ.
4. Добавьте обработку ошибок: лимиты, таймауты, недоступность модели.
5. Ограничьте длину запросов и ответов и ведите учёт расхода токенов.
6. Не отправляйте через API персональные данные без правовых оснований: учитывайте 152-ФЗ и место обработки данных.

### Пример
Интернет-магазин подключает модель через API к карточке товара. Скрипт отправляет характеристики и просит написать описание по заданному шаблону. Результат попадает редактору на проверку, а не сразу на сайт.

### Типичные ошибки
- Хранить ключ в публичном репозитории или на клиентской стороне сайта: его украдут.
- Не ставить лимиты расходов и не следить за использованием.
- Публиковать ответы модели без проверки.
- Привязаться к одной модели и не предусмотреть замену.
- Игнорировать задержки: ответ модели может идти секунды.

### Чем отличается от чата
Чат — готовый интерфейс для человека. API — способ программно использовать ту же модель в вашем продукте, настроив инструкции, форматы и интеграции.

### Частый вопрос
**Нужно ли уметь программировать, чтобы использовать API модели?** Для прямой работы нужно хотя бы базовое умение отправлять запросы. Без кода это можно сделать через конструкторы автоматизации вроде Zapier или n8n, которые подключают API готовыми блоками.
