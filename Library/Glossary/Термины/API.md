# API

**English:** Application Programming Interface
**Категория:** [[Глоссарий — Веб-разработка]]
**URL:** nikalimp.ru/glossary/api

## Определение

API — это набор правил, по которым одна программа обращается к другой: какие запросы можно отправлять и в каком виде приходит ответ. Проще говоря, API — это «розетка» сервиса: вы не лезете внутрь, а подключаетесь по понятному интерфейсу.

Пример из жизни сайта: форма отправляет заявку в [[CRM]], сайт показывает погоду от внешнего сервиса, оплата проходит через [[Платёжный шлюз|платёжный шлюз]]. Везде это работа через API. Чаще всего в вебе встречается [[REST API]], реже — [[GraphQL]]. Данные обычно передаются в формате [[JSON]], а вызовы идут по протоколу [[HTTPS]].

Для обращения к API нужен адрес (endpoint), метод запроса (получить, создать, изменить, удалить) и, как правило, ключ доступа. Ответ приходит со статусом: 200 — всё хорошо, 404 — ничего не найдено, 500 — ошибка на стороне сервера.

### Пример
Запрос «дай список статей» отправляется на адрес вида `https://site.ru/api/articles`. Сервис отвечает JSON со списком: заголовки, даты, ссылки.

### Как безопасно пользоваться
1. Храните ключи доступа на сервере, а не в коде страницы.
2. Выдавайте ключам только нужные права.
3. Проверяйте лимиты запросов и обрабатывайте ошибки.
4. Используйте HTTPS.
5. Следите за версиями API: при смене версии старые вызовы могут сломаться.

### Типичные ошибки
- Публикация секретного ключа в открытом репозитории.
- Нет обработки ошибок: сайт «падает», когда сервис не отвечает.
- Зависимость от чужого API без запасного плана.
- Передача лишних персональных данных.

### Чем отличается от веб-страницы
Страница отдаёт человеку готовый вид (HTML), API — данные для программы. Одни и те же данные можно показать на сайте, в приложении и передать нейросети через [[MCP]].

### Типичные задачи, которые решает API на сайте
Передать заявку из формы в CRM, получить курс валюты, проверить оплату, отправить письмо, показать отзывы с карт, подключить поиск или чат-бота. Обычно разработчик читает документацию сервиса, получает ключ и пишет код, который отправляет запросы. Платформы автоматизации вроде [[Make (термин)|Make]] и [[Zapier (термин)|Zapier]] позволяют соединять сервисы без кода, но тоже работают через API.

### Частый вопрос
**Зачем сайту API, если есть готовые плагины?** Плагин решает типовую задачу, а API позволяет подключить любой сервис и настроить логику под себя. Для простых сайтов плагина хватает, для интеграций со сложными системами нужен API.
