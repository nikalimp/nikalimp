# CI/CD

**English:** Continuous Integration / Delivery
**Категория:** [[Глоссарий — Веб-разработка]]
**URL:** nikalimp.ru/glossary/ci-cd

## Определение

CI/CD — это автоматизация проверки и выкладки кода. CI (непрерывная интеграция) на каждое изменение запускает сборку и тесты. CD (непрерывная доставка или развёртывание) автоматически выкладывает проверенную версию на сервер.

Без CI/CD разработчик вручную собирает проект, загружает файлы по FTP и надеется, что ничего не сломалось. С CI/CD достаточно отправить изменения в репозиторий: система сама прогонит проверки и, если всё в порядке, выложит сайт. Если тесты упали, выкладка не произойдёт.

Наиболее известные инструменты: GitHub Actions, GitLab CI, Jenkins. Платформы вроде [[Vercel (термин)|Vercel]] и [[Netlify (термин)|Netlify]] встраивают CD в хостинг: выкладка запускается сама после коммита. Процесс опирается на [[Git]] и [[Репозиторий|репозиторий]].

### Пример
Разработчик создаёт [[Pull request]]. CI запускает [[Линтер|линтер]], [[Юнит-тест|юнит-тесты]] и сборку. После проверки и слияния CD выкладывает новую версию на [[Стейджинг|стейджинг]], а затем в продакшн.

### Из чего состоит конвейер
1. Получение кода из ветки.
2. Установка зависимостей.
3. Проверка: линтер, тесты, сборка.
4. Публикация результата (деплой).
5. Уведомление команде и возможность откатить версию.

### Типичные ошибки
- Хранить пароли и ключи в коде вместо секретов системы. Используйте [[Переменные окружения]].
- Нет тестов, и CI проверяет только то, что проект собирается.
- Автоматический деплой в продакшн без возможности отката.
- Слишком долгий конвейер, который никто не ждёт.

### Кому это нужно
Командам и проектам, которые часто обновляются: сервисам, интернет-магазинам, блогам с регулярными публикациями. Для статичного сайта-визитки достаточно простой автоматической выкладки.

### Какие инструменты используют
В небольших проектах чаще всего берут GitHub Actions: сценарий описывается в файле внутри репозитория и запускается на каждое событие, например при слиянии изменений. Для сайтов на статической генерации достаточно трёх шагов: установить зависимости, собрать сайт, выложить результат. Для сервисов добавляют тесты, проверку безопасности и миграции базы данных.

### Частый вопрос
**CI/CD нужен только больших командам?** Нет. Даже одному разработчику автоматическая сборка и выкладка экономят время и снижают риск ошибки при ручном деплое. Настройка простого конвейера занимает несколько часов.
