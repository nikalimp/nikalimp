# CNAME

**English:** CNAME Record
**Категория:** [[Глоссарий — Хостинг, домены, инфраструктура]]
**URL:** nikalimp.ru/glossary/cname

## Определение

CNAME-запись (Canonical Name Record) — тип записи в [[DNS]], который делает одно доменное имя псевдонимом другого. Вместо IP-адреса в ней указывается имя: запросы к псевдониму направляются туда, куда ведёт целевое имя.

Например, запись `www.site.ru → CNAME → site.ru` говорит: «адрес www — то же самое, что и site.ru». Если вы потом поменяете [[A-запись]] основного домена на новый IP, поддомен www подхватит изменение автоматически, ничего менять не придётся. Поэтому CNAME удобно использовать там, где адрес сервера может меняться без вашего участия.

Типичный случай — подключение домена к платформе: конструктору, облачному хостингу или сервису рассылок. Платформа даёт вам имя вроде `shop.example-platform.com`, вы создаёте CNAME для своего поддомена, и она сама управляет IP-адресами.

### Пример
Вы хотите, чтобы блог открывался по адресу blog.site.ru и работал на стороннем сервисе:
- имя: `blog`
- тип: CNAME
- значение: адрес, который выдал сервис (например, `cname.service-example.com`)

### Ограничения CNAME
1. На одном имени не может быть CNAME и других записей одновременно (A, MX, TXT). Поэтому CNAME нельзя ставить на корень домена (`@`), где обязательно живут [[NS-сервер|NS]] и [[MX-запись|MX]] записи. Некоторые DNS-провайдеры обходят это ограничение собственным механизмом (ALIAS, ANAME или «CNAME flattening»), но это не стандартный тип записи.
2. Значением должно быть имя, а не IP-адрес.
3. Цепочки из нескольких CNAME подряд замедляют разрешение имени, их лучше не строить.

### Как создать CNAME
1. Откройте управление DNS у регистратора или провайдера DNS.
2. Создайте запись типа CNAME для нужного поддомена.
3. Вставьте значение ровно так, как указано в инструкции сервиса, обычно без `https://` и без слеша в конце.
4. Сохраните и дождитесь обновления DNS.
5. Проверьте запись командой `nslookup` или онлайн-сервисом.

### Типичные ошибки
- Пытаются поставить CNAME на корневой домен, где уже есть другие записи.
- Вписывают в значение полный URL со схемой `https://`.
- Создают CNAME для поддомена, на котором уже есть A-запись: две записи конфликтуют.
- Включают проксирование в [[Cloudflare (термин)|Cloudflare]], не прочитав инструкцию сервиса, и подтверждение домена не проходит.

### Чем отличается от A-записи
A-запись указывает на IP-адрес сервера, CNAME — на другое имя. A проще и работает на корне домена, CNAME гибче при смене инфраструктуры.

### Частый вопрос
**Можно ли использовать CNAME для основного домена site.ru?** По стандарту нет: на корне домена должны быть другие обязательные записи. Для основного домена используют A-запись или специальные функции провайдера DNS, а CNAME оставляют для поддоменов вроде www, blog или shop.
