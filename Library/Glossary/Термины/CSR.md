# CSR

**English:** Client-Side Rendering
**Категория:** [[Глоссарий — Веб-разработка]]
**URL:** nikalimp.ru/glossary/csr

## Определение

CSR (клиентский рендеринг) — это способ построения страниц, при котором сервер отдаёт почти пустой HTML и скрипт, а содержимое страницы собирает JavaScript прямо в браузере пользователя.

Так работают одностраничные приложения ([[SPA]]) на React, Vue и Angular. Браузер загружает скрипт, скрипт запрашивает данные у [[API]] и рисует интерфейс. Плюс подхода — быстрые переходы между экранами после первой загрузки и «приложенческое» поведение. Минус — первая загрузка тяжелее, а контент появляется только после выполнения кода.

Противоположные подходы: [[SSR]], когда HTML собирается на сервере при каждом запросе, и [[SSG]], когда страницы готовятся заранее при сборке. Часто их комбинируют: например, [[Next.js (термин)|Next.js]] позволяет выбирать способ для каждой страницы.

### Чем CSR плох для сайтов с контентом
Поисковые роботы и [[AI-краулер|AI-краулеры]] видят только то, что получили в HTML. Яндекс и Google умеют выполнять JavaScript, но делают это не всегда и не сразу. Многие AI-боты скрипты не выполняют вовсе, и страница на CSR выглядит для них пустой.

### Как проверить, что страница не пустая для робота
1. Откройте страницу и выберите «Просмотр кода страницы» (не инспектор).
2. Найдите в исходном HTML заголовок и основной текст.
3. Если текста нет, а есть только `<div id="root"></div>`, страница построена на CSR.
4. Дополнительно используйте проверку страницы в [[Яндекс Вебмастер (термин)|Яндекс Вебмастере]].

### Где CSR подходит
В закрытых кабинетах, [[Админка|админках]], дашбордах и сервисах, которые не нужно индексировать.

### Типичные ошибки
- Делать на CSR лендинг или блог и ждать результатов в поиске.
- Отдавать пустой экран без индикатора загрузки.
- Загружать один огромный скрипт вместо [[Code splitting|разделения кода]].

### Чем CSR отличается от SSR на примере
При CSR браузер получает пустую оболочку и ждёт, пока скрипт построит страницу, при SSR — готовый HTML с текстом. В первом случае пользователь сначала видит белый экран или индикатор загрузки, во втором — содержимое сразу, а интерактивность подключается позже ([[Гидратация]]). Для коммерческих страниц, где важен первый экран, второй вариант обычно надёжнее.

### Частый вопрос
**CSR вредит SEO?** Не всегда, но создаёт риск: индексация медленнее и менее надёжна. Для публичных страниц с текстом безопаснее выбирать SSR или SSG.
