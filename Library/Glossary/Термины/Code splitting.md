# Code splitting

**English:** Code Splitting
**Категория:** [[Глоссарий — Веб-разработка]]
**URL:** nikalimp.ru/glossary/code-splitting

## Определение

Code splitting (разделение кода) — это приём, при котором JavaScript-код сайта делится на несколько небольших файлов, и браузер загружает только те части, которые нужны для текущей страницы.

Без разделения весь код приложения попадает в один большой файл ([[Бандл|бандл]]). Посетитель главной страницы скачивает код кабинета, редактора и страницы оплаты, которые ему пока не нужны. Это замедляет загрузку, ухудшает [[LCP]] и [[INP]], а значит и [[Core Web Vitals]].

Разделение делает сборщик: Webpack, Vite и другие. Современные фреймворки, например [[Next.js (термин)|Next.js]], делят код по страницам автоматически. Дополнительно разработчик может отложить загрузку тяжёлых компонентов до момента, когда они понадобятся. Это похоже на [[Lazy loading]], только для кода, а не для изображений.

### Виды разделения
- По страницам (маршрутам): у каждой страницы свой файл.
- По компонентам: тяжёлый график или редактор загружается по клику.
- Выделение общих библиотек в отдельный файл, который кэшируется браузером ([[Кэширование]]).

### Пример
Динамический импорт в [[JavaScript]]: код редактора подгружается, только когда пользователь нажал «Редактировать».
```js
const { Editor } = await import('./editor.js');
```

### Как проверить, нужно ли оно сайту
1. Откройте [[PageSpeed Insights]] или [[Lighthouse (термин)|Lighthouse]].
2. Найдите предупреждения «Уменьшите объём неиспользуемого JavaScript».
3. Посмотрите размер бандла анализатором сборки.
4. Определите крупные библиотеки, которые нужны не на всех страницах.
5. Вынесите их в динамическую загрузку и сравните результат.

### Типичные ошибки
- Делить на слишком мелкие файлы: каждый запрос тоже стоит времени.
- Откладывать код, нужный для первого экрана: интерфейс «мигает».
- Не проверять результат после изменений.
- Забывать про [[Tree shaking|tree shaking]], который убирает неиспользуемый код полностью.

### Как это связано с метриками
Меньше загружаемого кода — быстрее появление главного элемента и раньше страница реагирует на действия. Поэтому разделение кода напрямую влияет на [[LCP]] и [[INP]]. Эффект особенно заметен на мобильных устройствах со слабыми процессорами, где разбор тяжёлого JavaScript занимает много времени. Начинайте с самых крупных файлов: именно они дают наибольший выигрыш.

### Частый вопрос
**Нужно ли разделение кода обычному сайту на Tilda или WordPress?** Обычно нет: там вы не управляете сборкой JavaScript. Приём актуален для приложений и сайтов на современных фреймворках, где объём скриптов может вырасти до мегабайтов.
