# Core Web Vitals

**Категория:** [[Глоссарий — Веб-разработка]]
**URL:** nikalimp.ru/glossary/core-web-vitals

## Определение

Core Web Vitals — это набор метрик Google, которые измеряют, как пользователи воспринимают загрузку, отзывчивость и визуальную стабильность страницы. Сейчас в него входят три показателя: [[LCP]], [[INP]] и [[CLS]].

Метрики основаны на реальных данных посетителей. Они показывают не «скорость сайта вообще», а конкретные моменты: когда появился главный контент, как быстро страница реагирует на действия и прыгает ли вёрстка. Google включил их в оценку качества страниц как часть пользовательского опыта, но это один из многих сигналов: релевантность и полезность контента остаются важнее.

Скорость загрузки и стабильность страницы важны и для российских поисковых систем: смотрите отчёты [[Яндекс Метрика (термин)|Метрики]] и [[Яндекс Вебмастер (термин)|Вебмастера]] о качестве сайта вместе с отчётом Google.

### Три метрики и целевые значения
- LCP (скорость загрузки главного элемента): хорошо — до 2,5 секунды.
- INP (отзывчивость на нажатия и клики): хорошо — до 200 миллисекунд.
- CLS (смещение элементов во время загрузки): хорошо — не больше 0,1.

Значения оценивают по 75-му процентилю реальных посещений: чтобы страница считалась хорошей, этим порогам должны соответствовать не меньше трёх четвертей визитов.

### Как проверить
1. Откройте [[PageSpeed Insights]] и введите адрес страницы.
2. Посмотрите блок с реальными данными пользователей, если их достаточно.
3. Изучите лабораторные данные [[Lighthouse (термин)|Lighthouse]] и список рекомендаций.
4. Для всего сайта используйте отчёт Core Web Vitals в [[Google Search Console (термин)|Google Search Console]].
5. Повторите проверку после правок, но учтите, что реальные данные обновляются с задержкой.

### Что чаще всего улучшает показатели
- Сжатие и современные форматы изображений ([[WebP]], [[AVIF]]).
- Размеры для картинок и резерв места под блоки.
- Меньше JavaScript, [[Code splitting|разделение кода]].
- [[CDN]] и [[Кэширование|кэширование]].

### Типичные ошибки
- Гнаться за 100 баллами Lighthouse, хотя пользователям важнее реальные метрики.
- Проверять только главную страницу.
- Оптимизировать лабораторные данные и не смотреть полевые.

### Что считать хорошим результатом для бизнеса
Цель не в идеальных цифрах, а в том, чтобы реальные посетители не ждали и не промахивались. Если большинство визитов укладывается в пороговые значения, дальнейшая оптимизация даёт меньше отдачи, чем работа над контентом и оффером. Но для интернет-магазинов и сервисов с формами каждая сотая секунда отзывчивости заметнее: там метрики напрямую связаны с продажами.

### Частый вопрос
**Сильно ли Core Web Vitals влияют на позиции?** Влияют умеренно: это один из сигналов, а не решающий фактор. Если контент слабый, быстрая загрузка не спасёт. Зато при равном качестве страниц быстрый и стабильный сайт выигрывает и в поиске, и в конверсии.
