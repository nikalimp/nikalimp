# DOM

**English:** Document Object Model
**Категория:** [[Глоссарий — Веб-разработка]]
**URL:** nikalimp.ru/glossary/dom

## Определение

DOM (Document Object Model) — это представление HTML-страницы в виде дерева объектов, с которым может работать JavaScript. Каждый тег, атрибут и кусок текста становится узлом дерева, и скрипт может его найти, изменить или удалить.

Когда браузер получает [[HTML]], он разбирает его и строит DOM. Затем объединяет его со стилями [[CSS]] и рисует страницу. Если скрипт меняет DOM, например добавляет карточку товара, браузер перерисовывает нужный участок. Так работают меню, модальные окна, фильтры и живые формы.

Важно: DOM — это не исходный код страницы. Исходный HTML вы видите через «Просмотр кода», а DOM — во вкладке «Элементы» в инструментах разработчика. Они различаются, если страницу достраивает [[JavaScript]].

Дерево устроено по принципу родителей и детей: у тега `body` есть потомки `header`, `main`, `footer`, а у них свои. Скрипт может подняться вверх по дереву, спуститься вниз или перейти к соседнему узлу, а браузер следит за любыми изменениями и обновляет экран. Работать с деревом можно не только руками: фреймворки вроде React держат в памяти свою копию дерева и обновляют настоящий DOM минимальными порциями, чтобы интерфейс не тормозил.

### Пример
В HTML есть заголовок `<h1 id="title">Привет</h1>`. Скрипт `document.getElementById("title").textContent = "Здравствуйте"` находит узел по идентификатору и меняет его текст. В исходном файле осталось «Привет», а пользователь видит «Здравствуйте».

### Как посмотреть DOM страницы
1. Откройте страницу в Chrome или Яндекс Браузере.
2. Нажмите F12 или правой кнопкой по элементу и «Просмотреть код».
3. Перейдите на вкладку «Elements» («Элементы»).
4. Раскрывайте узлы дерева: справа видны применённые стили.

### Почему DOM важен для скорости и SEO
- Большой DOM с тысячами узлов замедляет отрисовку и работу скриптов, это бьёт по метрикам [[Core Web Vitals]].
- Если текст появляется в DOM только после выполнения скриптов, поисковый робот или [[AI-краулер]] может его не увидеть. Надёжнее отдавать контент уже в HTML, как делают [[SSR]] и [[SSG]].
- Глубокая вложенность тегов усложняет вёрстку и поддержку.

### Типичные ошибки
- Делать лишние обёртки из div там, где хватает одного тега.
- Менять DOM скриптом по одному элементу в цикле вместо одной пакетной вставки.
- Прятать важный текст в элементы, которые создаются только после клика.

### Частый вопрос
**Чем DOM отличается от HTML?** HTML — это текстовый файл с разметкой, который отдаёт сервер. DOM — живая структура в памяти браузера, построенная из этого файла и изменённая скриптами. Поэтому то, что видит пользователь, может отличаться от исходного кода страницы.
