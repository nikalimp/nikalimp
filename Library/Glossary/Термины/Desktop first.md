# Desktop first

**English:** Desktop First
**Категория:** [[Глоссарий — UI-UX дизайн]]
**URL:** nikalimp.ru/glossary/desktop-first

## Определение

Desktop first — подход к проектированию, при котором интерфейс сначала делают для широкого экрана компьютера, а затем адаптируют под планшеты и телефоны.

Это противоположность подходу [[Mobile first]]. В Desktop first дизайнер рисует макет на десктопной сетке (например, 1440 px), располагает много колонок, боковые панели, подробные таблицы, а потом упрощает: колонки складываются в одну, меню прячется в бургер, второстепенные блоки скрываются. В CSS это выражается через media-запросы с max-width: стили описаны для большого экрана, а для малых переопределяются.

### Когда подход оправдан
- Рабочие инструменты: админки, CRM, аналитика, редакторы, где пользователи сидят за компьютером.
- Сложные таблицы и дашборды, которым нужно много места.
- Аудитория, которая по данным аналитики и Метрики почти полностью заходит с десктопа.
- B2B-сервисы, которыми пользуются на работе.

### Риски
Подход соблазняет перенести на телефон всё, что есть на десктопе, и получить перегруженный экран. Мобильная версия превращается в урезанную копию, а не в продуманный сценарий. Кроме того, мобильный трафик в России и в мире составляет значительную долю, поэтому для публичных сайтов такой подход обычно рискован.

### Как работать с Desktop first аккуратно
1. Заранее определите главное действие и сохраните его на всех размерах экрана.
2. Задайте брейкпоинты по содержимому, а не по моделям устройств.
3. Проверяйте touch-сценарии: кнопки и ссылки должны достигать размера [[Touch target]].
4. Тестируйте на реальных телефонах, а не только в режиме эмуляции.
5. Следите за скоростью: десктопные скрипты и картинки не должны грузиться на мобильных зря.

### Пример
Сервис учёта заказов для менеджеров: на десктопе таблица на 12 колонок, фильтры слева и панель деталей справа. На планшете фильтры уходят в выезжающую панель, на телефоне остаётся список карточек с тремя ключевыми полями.

### Типичные ошибки
- Прятать на мобильной версии важное, считая его «второстепенным».
- Делать hover-подсказки, недоступные на тач-экране.
- Не проверять горизонтальную прокрутку на узких экранах.

### Кому и когда это нужно
Командам, которые проектируют рабочие панели, CRM, конструкторы и аналитические сервисы. Для маркетинговых сайтов, блогов и интернет-магазинов подход почти всегда уступает Mobile first, потому что значительная часть заходов приходится на телефоны. Решение лучше принимать по данным Яндекс Метрики о реальных устройствах аудитории.

### Частый вопрос
**Что выбрать для сайта услуг?** Mobile first: значительная часть посетителей приходит с телефона, и поисковики оценивают мобильную версию. Desktop first разумен для внутренних рабочих инструментов.
