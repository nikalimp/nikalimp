## Определение

Docker — это платформа для упаковки приложения вместе со всем, что ему нужно для работы, в изолированный контейнер, который одинаково запускается на любом компьютере и сервере.

Раньше приложение работало у разработчика и ломалось на сервере: другая версия Node.js, нет нужной библиотеки, иначе настроена система. Docker решает это. Вы описываете окружение в файле Dockerfile: базовая система, зависимости, команда запуска. По нему собирается образ, а запущенный образ называется контейнером. Контейнер лёгкий, запускается за секунды и не мешает соседним приложениям на том же сервере.

Docker появился в 2013 году и стал стандартом для выкладки сервисов. Для обычных сайтов на готовых платформах вроде [[Vercel (термин)]] или [[Netlify (термин)]] он не нужен, а вот для веб-сервисов с базой данных и фоновыми задачами используется очень часто.

Для небольших проектов Docker даёт ещё одно преимущество: новому разработчику не нужно часами настраивать компьютер. Он клонирует проект, выполняет одну команду, и всё запускается так же, как у остальных в команде и на сервере. Готовые образы популярных программ, от баз данных до веб-серверов, лежат в открытом каталоге Docker Hub, и поднять нужный сервис можно одной командой.

### Основные понятия
- Образ — шаблон приложения, из которого создаются контейнеры.
- Контейнер — запущенный экземпляр образа.
- Dockerfile — инструкция сборки образа.
- Docker Compose — файл, который запускает несколько контейнеров вместе, например сайт и базу данных.

### Как запустить приложение в Docker
1. Установите Docker Desktop или Docker Engine на сервере.
2. Создайте в проекте Dockerfile с базовым образом и командой запуска.
3. Соберите образ командой `docker build`.
4. Запустите контейнер командой `docker run` и откройте нужный порт.
5. Для связки с базой опишите сервисы в `docker-compose.yml`.

### Типичные ошибки
- Хранить данные базы внутри контейнера без тома: при пересоздании всё пропадёт.
- Класть секреты и ключи прямо в образ.
- Тянуть тяжёлый базовый образ, когда хватает лёгкого.
- Не фиксировать версии базового образа.

### Чем отличается от виртуальной машины
Виртуальная машина содержит целую операционную систему и запускается минутами. Контейнеры используют ядро хозяйской системы, поэтому легче и быстрее, но изолированы чуть слабее.

### Частый вопрос
**Нужен ли Docker для сайта?** Для статического сайта или лендинга обычно нет: его выкладывают через [[Git]] и хостинг. Docker нужен, если у проекта есть собственный сервер, база данных или несколько сервисов, которые должны одинаково работать у разработчика и на продакшене.
