# Focus

**English:** Focus State
**Категория:** [[Глоссарий — UI-UX дизайн]]
**URL:** nikalimp.ru/glossary/focus

## Определение

Focus — состояние фокуса: элемент интерфейса выбран и готов принимать ввод или нажатие, чаще всего при навигации с клавиатуры.

Когда пользователь нажимает Tab, браузер переводит фокус по ссылкам, кнопкам и полям. Сфокусированный элемент должен быть заметно выделен: обводкой, контуром, изменением цвета. Это один из базовых состояний элемента, наряду с [[Hover]] и [[Disabled]]. Для людей, которые не пользуются мышью (при проблемах с моторикой, зрением, а также опытных пользователей, работающих с клавиатуры), видимый фокус — единственный способ понять, где они находятся.

### Почему это важно
Без видимого фокуса клавиатурная навигация превращается в слепое блуждание. Рекомендации WCAG требуют, чтобы индикатор фокуса был виден, а в версии 2.2 добавлены уточнения по его размеру и контрасту. Для сайтов, которыми пользуются государственные и крупные коммерческие организации, это ещё и вопрос соответствия требованиям доступности.

### Как оформить фокус
1. Не удаляйте стандартный outline, если не заменяете его другим выделением.
2. Используйте псевдокласс :focus-visible: он показывает рамку при навигации с клавиатуры и не мешает при клике мышью.
3. Обеспечьте контраст индикатора с фоном и самим элементом, не меньше 3:1.
4. Сделайте контур толщиной не меньше 2 px и с небольшим отступом от границы.
5. Проверьте порядок обхода по Tab: он должен совпадать с визуальным порядком.
6. Не пропускайте интерактивные элементы и не оставляйте «ловушек» с фокусом внутри окон.

### Пример
Форма обратной связи: при нажатии Tab фокус переходит на поле имени, телефон, согласие и кнопку. Каждое поле получает синий контур толщиной 2 px. После отправки фокус перемещается на сообщение об успехе, чтобы пользователь экранного диктора услышал результат.

### Типичные ошибки
- Глобальное правило outline: none без замены.
- Фокус едва заметен: светло-серая рамка на белом фоне.
- Модальное окно открывается, а фокус остаётся на странице под ним.
- Порядок Tab прыгает по странице из-за позиционирования через CSS.
- Кастомные элементы на div без tabindex и ролей недоступны с клавиатуры.

### Чем отличается от hover
Hover возникает при наведении мыши и недоступен на сенсорных экранах и с клавиатуры. Focus работает при навигации клавиатурой и экранными читалками. Любое оформление наведения стоит дублировать для фокуса.

### Кому и когда это нужно
Каждому, кто верстает или проектирует интерфейс. Проверка фокуса занимает пару минут: откройте страницу, нажмите Tab и пройдите по ней, не касаясь мыши. Если вы теряете, где находитесь, или не можете нажать на нужный элемент, то же происходит у людей, которые пользуются клавиатурой постоянно.

### Частый вопрос
**Можно ли убрать обводку фокуса, потому что она некрасивая?** Нельзя без замены. Если стандартная обводка не подходит по стилю, нарисуйте свою, заметную и контрастную. Невидимый фокус — частая ошибка, из-за которой сайт нельзя использовать с клавиатуры.
