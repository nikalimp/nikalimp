# Git

**Категория:** [[Глоссарий — Веб-разработка]]
**URL:** nikalimp.ru/glossary/git

## Определение

Git — это система контроля версий: программа, которая запоминает каждое изменение в файлах проекта, позволяет вернуться к любой прежней версии и работать над кодом нескольким людям одновременно.

Git создал Линус Торвальдс в 2005 году для разработки ядра Linux. Он распределённый: у каждого участника на компьютере лежит полная история проекта, а не только последняя версия. Это значит, что можно работать без интернета, а потерять историю из-за поломки одного сервера невозможно.

Для сайтов Git решает три задачи: хранит историю правок, позволяет безопасно пробовать новое и служит основой выкладки. Современные платформы вроде [[Vercel (термин)]] и [[Netlify (термин)]] публикуют сайт автоматически, когда вы отправляете изменения в репозиторий на [[GitHub (термин)]].

Git хранит не копии файлов, а цепочку снимков состояния проекта. Благодаря этому можно сравнить любые две версии, найти момент, когда появилась ошибка, и откатить только одно изменение, не трогая остальные. Для дизайнеров и верстальщиков он тоже полезен: так сохраняют версии макетов и кода. Команд в ежедневной работе нужно немного: сохранить, отправить, получить чужие правки и переключиться между ветками. Остальное подтягивается по мере необходимости, а графические клиенты вроде GitHub Desktop избавляют от консоли.

### Основные понятия
- Репозиторий — папка проекта с историей.
- Коммит — сохранённый снимок изменений с описанием.
- Ветка — отдельная линия работы, чтобы не ломать основную.
- Слияние (merge) — объединение веток.
- Remote — копия репозитория на сервере, например на GitHub.

### Как начать работать
1. Установите Git и выполните `git init` в папке проекта.
2. Добавьте файлы командой `git add .`.
3. Сохраните снимок: `git commit -m "Добавил форму заявки"`.
4. Свяжите репозиторий с GitHub и отправьте код командой `git push`.
5. Для новой задачи создавайте ветку и вносите правки через [[Pull request]].

### Типичные ошибки
- Коммитить пароли, ключи и файлы `.env`: после отправки они остаются в истории.
- Писать сообщения вроде «правки»: через месяц непонятно, что менялось.
- Складывать в репозиторий тяжёлые видео и архивы.
- Работать сразу в основной ветке без проверки.

### Чем отличается от GitHub
Git — программа, которая работает на вашем компьютере. GitHub — сервис в интернете, где хранят репозитории Git, обсуждают изменения и запускают автоматические проверки. Есть и другие сервисы: GitLab, Bitbucket.

### Частый вопрос
**Нужен ли Git, если я делаю сайт один?** Да. Он страхует от неудачных правок, показывает, что и когда изменилось, и открывает автоматическую выкладку. Даже в одиночном проекте это занимает несколько минут настройки и экономит часы.
