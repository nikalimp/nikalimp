# Hreflang

**Категория:** [[Глоссарий — SEO]]
**URL:** nikalimp.ru/glossary/hreflang

## Определение

Hreflang — это атрибут `rel="alternate" hreflang`, который сообщает поисковикам, какие языковые и региональные версии есть у страницы, чтобы показывать пользователю подходящую.

Если у сайта есть версии на русском, английском и казахском, hreflang связывает их между собой. Человек из Алматы увидит страницу для Казахстана, а англоязычный пользователь из США — английскую версию. Без разметки поисковик может показать не ту версию или принять переводы за дубли.

Hreflang подсказывает, но не гарантирует выбор. Google и Яндекс учитывают его вместе с другими сигналами. Подробнее о задаче в целом — в статье [[Международное SEO]].

### Пример
В `<head>` страницы:

`<link rel="alternate" hreflang="ru" href="https://site.com/ru/">`
`<link rel="alternate" hreflang="en" href="https://site.com/en/">`
`<link rel="alternate" hreflang="x-default" href="https://site.com/">`

Значение `x-default` указывает версию по умолчанию для пользователей, чей язык не подошёл ни под одну из перечисленных.

### Как внедрить
1. Составьте список всех версий и соответствующих страниц.
2. Выберите способ: теги в `<head>`, HTTP-заголовки или [[Sitemap.xml]].
3. Укажите коды: язык по ISO 639-1 (`ru`, `en`), при необходимости регион по ISO 3166-1 (`ru-KZ`, `en-GB`).
4. Каждая страница ссылается на все версии, включая саму себя.
5. Проверьте, что страницы ссылаются друг на друга взаимно.

### Типичные ошибки
- Нет обратных ссылок: если A указывает на B, B обязана указывать на A, иначе разметка игнорируется.
- Неверные коды: например, `en-UK` вместо `en-GB`.
- Hreflang указывает на адрес, который редиректит или закрыт от индексации.
- Конфликт с [[Canonical]]: страница указывает canonical на другую версию.
- Автоматический редирект по языку браузера, из-за чего робот не видит все версии.

### Чем отличается от canonical
Canonical выбирает главный адрес среди дублей. Hreflang связывает разные версии, которые не являются дублями, а предназначены для разных аудиторий.

### Кому и когда это нужно
Hreflang нужен сайтам с несколькими языками или странами: интернет-магазинам, SaaS-сервисам, компаниям с офисами в разных странах. Он полезен и для одного языка с разными регионами, если контент отличается: цены, валюта, доставка. Внедряйте разметку на этапе запуска новых версий, пока в индексе нет путаницы, а проверку проводите после каждого изменения структуры сайта.

### Частый вопрос
**Нужен ли hreflang, если сайт только на русском?** Нет. Он нужен, когда у страницы есть несколько языковых или региональных версий. Для одной русскоязычной версии разметка бесполезна.
