# JAMstack

**Категория:** [[Глоссарий — Веб-разработка]]
**URL:** nikalimp.ru/glossary/jamstack

## Определение

JAMstack — это подход к созданию сайтов, при котором страницы собираются заранее в готовые файлы (Markup), а динамика подключается через JavaScript и внешние API. Название складывается из первых букв: JavaScript, APIs, Markup.

Идея в том, чтобы не собирать страницу на сервере при каждом запросе. Сайт строится один раз, раскладывается по [[CDN]] и отдаётся мгновенно. Всё, что требует серверной логики, — формы, оплата, поиск, регистрация, — вызывается через [[API]] отдельных сервисов. Термин ввели около 2015 года, его популяризировали Netlify и другие платформы.

Из этого получается ряд преимуществ. Сайт быстрый, потому что отдаёт готовые файлы. Безопасный, потому что нет сервера с базой, которую можно взломать. Дешёвый в хостинге и простой в масштабировании.

Сейчас термин используют реже, потому что границы размылись: большинство современных фреймворков умеет и собирать статику, и выполнять код на сервере, и обновлять страницы на лету. Но принципы — готовые страницы, CDN, подключаемые сервисы — остаются основой быстрых сайтов. Поэтому, если вы выбираете технологию для лендинга, блога или каталога, смысл подхода стоит понимать, даже если никто не называет стек этим словом.

### Из чего состоит
- Генератор статического сайта, например Next.js, Astro, Hugo: см. [[SSG]].
- [[Headless CMS]] или файлы Markdown для контента.
- Хостинг и CDN: [[Netlify (термин)]], [[Vercel (термин)]], [[Cloudflare (термин)]].
- Внешние API для форм, платежей и поиска.
- Репозиторий в [[Git]]: каждое изменение запускает новую сборку.

### Пример
Сайт-визитка: страницы собраны из Markdown, форма заявки отправляет данные в Telegram через функцию в облаке, а сайт лежит на CDN. Нет базы данных и панели, которую нужно обновлять.

### Как понять, подходит ли подход
1. Содержимое страниц меняется не чаще чем раз в несколько минут.
2. Персональные данные посетителей не нужно показывать на странице.
3. Динамические части можно вынести в отдельные запросы.
4. Команда готова работать с Git и сборкой.

### Типичные ошибки
- Применять подход к сервису с постоянно меняющимися данными для каждого пользователя.
- Не продумать, как редакторы будут обновлять контент.
- Подключить десятки сторонних API и получить хрупкую систему.
- Долго ждать пересборки большого сайта, не используя [[ISR]].

### Частый вопрос
**JAMstack всё ещё актуален?** Само название встречается реже, но идея стала нормой: статическая сборка плюс API вшита в современные фреймворки. Сегодня чаще говорят «статика с динамическими вставками» или гибридный рендеринг, а принцип тот же.
