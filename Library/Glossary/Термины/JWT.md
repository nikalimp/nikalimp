# JWT

**English:** JSON Web Token
**Категория:** [[Глоссарий — Веб-разработка]]
**URL:** nikalimp.ru/glossary/jwt

## Определение

JWT (JSON Web Token) — это компактный токен в формате [[JSON]], которым сервер подтверждает, кто сделал запрос. Он содержит данные о пользователе и цифровую подпись, поэтому его нельзя подделать, не зная секретного ключа.

Токен состоит из трёх частей, разделённых точками: заголовок с типом и алгоритмом подписи, полезная нагрузка (например, идентификатор пользователя и срок действия) и подпись. Первые две части лишь закодированы, а не зашифрованы. Прочитать их может любой, а вот изменить так, чтобы подпись осталась верной, нельзя.

Стандарт описан в документе RFC 7519. Подпись можно сделать с общим секретом (HMAC) или парой ключей, открытым и закрытым (RSA, ECDSA). Второй вариант удобен, когда токен выпускает один сервис, а проверяют несколько других, не зная секрета. Читается название как «джот». Если токен слишком длинный, он увеличивает каждый запрос, поэтому лишние данные в него класть не стоит, достаточно идентификатора и ролей.

### Как это работает
1. Пользователь вводит логин и пароль.
2. Сервер проверяет данные и выпускает JWT с подписью.
3. Браузер сохраняет токен и прикладывает его к каждому следующему запросу, обычно в заголовке `Authorization`.
4. Сервер проверяет подпись и срок действия и отвечает без повторного ввода пароля.

Сервер не хранит сессию в базе: вся нужная информация лежит в самом токене. Это удобно для [[API]] и для сервисов, где несколько серверов обслуживают один сайт. На JWT построены многие системы входа, в том числе у [[Supabase (термин)]] и [[Firebase (термин)]]. Через него часто передают результат входа по [[OAuth]].

### Где хранить токен
- В cookie с флагами HttpOnly и Secure: защищено от чтения скриптом, см. [[Cookie]].
- В [[Local Storage]]: удобнее, но уязвимее, если на сайте возможна вставка чужого кода (XSS).

### Типичные ошибки
- Класть в токен пароли и персональные данные: содержимое читается любым.
- Делать токен без срока действия.
- Хранить секретный ключ подписи в публичном коде.
- Не уметь отозвать токен: его нельзя «выключить» до истечения срока без дополнительного списка отозванных.
- Передавать токен по HTTP без шифрования; нужен [[HTTPS]].

### Чем отличается от сессии
При классической сессии сервер хранит запись о входе, а браузеру отдаёт случайный идентификатор в cookie. Отозвать такую сессию легко. JWT самодостаточен, не требует базы при проверке, но труднее отзывается.

### Частый вопрос
**JWT шифрует данные?** Нет. Он их подписывает. Содержимое можно прочитать, поэтому секреты внутрь класть нельзя. Подпись защищает только от подделки, а не от подглядывания.
