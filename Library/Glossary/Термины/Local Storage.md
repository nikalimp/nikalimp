# Local Storage

**Категория:** [[Глоссарий — Веб-разработка]]
**URL:** nikalimp.ru/glossary/local-storage

## Определение

Local Storage — это хранилище в браузере, куда сайт может записывать небольшие данные в виде пар «ключ — значение» и читать их при следующих визитах. Данные остаются на устройстве пользователя, пока их не удалят.

Хранилище встроено в браузер и работает на [[JavaScript]]. Вы пишете `localStorage.setItem("theme", "dark")`, а при следующем открытии сайта читаете `localStorage.getItem("theme")` и включаете тёмную тему. Объём ограничен: обычно около 5 мегабайт на сайт. Хранить можно только строки, поэтому объекты превращают в текст через [[JSON]].

Данные привязаны к адресу сайта (протокол, домен, порт): другой сайт прочитать их не может. В отличие от [[Cookie]], они не отправляются на сервер с каждым запросом.

Хранилище синхронное: чтение и запись блокируют основной поток. Для нескольких ключей это незаметно, но складывать в него большие объёмы данных не стоит, иначе интерфейс начнёт подтормаживать. Если сайту нужно синхронизировать данные между устройствами пользователя, одного локального хранилища недостаточно: для этого данные сохраняют на сервере и привязывают к аккаунту.

### Для чего используют
- Выбор темы оформления и языка.
- Черновики форм и заметок.
- Состояние интерфейса: свёрнутые блоки, выбранные фильтры.
- Корзина в простых магазинах до оформления заказа.

### Как пользоваться
1. Запишите значение: `localStorage.setItem("lang", "ru")`.
2. Прочитайте: `localStorage.getItem("lang")`.
3. Удалите: `localStorage.removeItem("lang")`.
4. Для объекта преобразуйте его: `JSON.stringify(obj)` перед записью и `JSON.parse(...)` после чтения.
5. Оберните работу с хранилищем в проверку на ошибки: в приватном режиме или при заполненном лимите запись может не пройти.

### Типичные ошибки
- Хранить пароли, токены и персональные данные. Любой скрипт на странице читает хранилище, а при уязвимости XSS данные уйдут злоумышленнику. Для токенов безопаснее cookie с флагом HttpOnly, см. [[JWT]].
- Считать данные надёжными: пользователь может очистить их, а браузер сам удалить при нехватке места.
- Хранить в нём то, что должно быть на сервере.
- Не учитывать согласие пользователя: если данные идентифицируют человека, правила использования ближе к cookie, и нужен [[Cookie-баннер]].

### Чем отличается от cookie и sessionStorage
Cookie уходят на сервер с каждым запросом и имеют срок действия. Local Storage остаётся только в браузере и не имеет срока. SessionStorage работает так же, но очищается при закрытии вкладки.

### Частый вопрос
**Сколько данных можно хранить в Local Storage?** Обычно около 5 мегабайт на один сайт, точный лимит зависит от браузера. Для больших объёмов используют IndexedDB, а важные данные лучше хранить на сервере.
