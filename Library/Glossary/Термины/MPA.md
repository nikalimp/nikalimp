# MPA

**English:** Multi-Page Application
**Категория:** [[Глоссарий — Веб-разработка]]
**URL:** nikalimp.ru/glossary/mpa

## Определение

MPA (Multi-Page Application, многостраничное приложение) — это сайт, где каждая страница является отдельным HTML-документом: при переходе по ссылке браузер загружает новую страницу целиком.

Так устроено большинство сайтов в интернете: лендинги, блоги, интернет-магазины, корпоративные сайты. Каждому адресу соответствует свой файл или своя страница, сгенерированная на сервере. Нажали «Контакты» — браузер запросил страницу /contacts, получил новый [[HTML]] и показал его.

Противоположный подход — [[SPA]] (одностраничное приложение): браузер один раз загружает оболочку, а дальше скрипт сам подменяет содержимое без перезагрузки. На практике сейчас сайты часто гибридные: современные фреймворки вроде [[Next.js (термин)]] дают URL и HTML для каждой страницы, а переходы делают быстрыми.

Название появилось как противопоставление SPA, когда одностраничные приложения стали модными. По сути MPA — это классическая модель веба, на которой он вырос, и она по-прежнему остаётся самой надёжной для контентных сайтов. Для скорости такие сайты используют кэш и предзагрузку: браузер подгружает следующую страницу заранее, и переход выглядит почти мгновенным.

### Чем хорош MPA
- Каждая страница имеет собственный адрес и готовый HTML. Поисковые роботы и [[AI-краулер]] читают её без выполнения скриптов.
- Проще SEO: у страницы свои заголовок, описание и содержание.
- Быстрый первый показ, потому что браузер сразу получает готовую разметку.
- Проще аналитика: каждая страница — отдельный просмотр в Метрике.
- Меньше зависимости от тяжёлого [[JavaScript]].

### Минусы
- При переходе страница перезагружается, возможно мигание.
- Общие части вроде шапки загружаются каждый раз, хотя кэш браузера смягчает проблему.
- Сложнее делать интерфейсы с постоянным состоянием, как в почтовом клиенте.

### Как понять, что вам нужен MPA
1. На сайте много страниц с текстом, которые должны искаться в Яндексе и Google.
2. Главная цель — показать услугу, продать товар, получить заявку.
3. Нет сложного интерфейса, который должен работать как программа.
4. Важны скорость первой загрузки и доступность без скриптов.

### Типичные ошибки
- Выбирать SPA ради моды, когда нужен простой сайт услуг: теряется индексация и растёт нагрузка.
- Дублировать шапку и подвал в каждом файле вручную без шаблона.
- Не настраивать кэширование общих файлов.

### Частый вопрос
**MPA или SPA для сайта услуг?** Для сайта услуг, блога и каталога выбирайте MPA или гибрид с готовым HTML на каждой странице: так проще индексация в Яндексе и поиск нейросетей. SPA подходит личным кабинетам, дашбордам и сервисам, где важнее работа интерфейса, чем поисковый трафик.
