## Определение

Next.js — это фреймворк на базе [[React (термин)|React]], который добавляет к библиотеке маршрутизацию, серверный рендеринг и всё остальное, что нужно для готового сайта или веб-приложения. Его разрабатывает компания Vercel, код открытый.

Сам React умеет только собирать интерфейс из компонентов в браузере. Всё остальное приходится выбирать самому: как устроены адреса страниц, где рендерить, как грузить данные. Next.js решает эти вопросы за вас. Страницы создаются как файлы в папке `app` или `pages`, и каждому файлу соответствует адрес. Для каждой страницы можно выбрать способ отдачи: [[SSR]] на сервере по запросу, [[SSG]] при сборке или обычный рендеринг в браузере.

Главная причина популярности для маркетинга и SEO: страница приходит в браузер и к поисковому роботу уже с готовым HTML-текстом. Яндекс и Google читают такой контент без выполнения скриптов, а скорость загрузки выше, чем у чистого [[SPA]]. Для ИИ-краулеров это тоже важно: многие из них не выполняют JavaScript.

В России Next.js часто выбирают для корпоративных сайтов, каталогов и сервисов, где важны индексация в Яндексе и скорость. Фреймворк даёт много настроек, поэтому проект стоит начинать с чёткого решения: какие страницы статические, какие динамические, где нужна авторизация. Тогда сайт получается быстрым, а хостинг не требует лишних затрат.

### Что входит из коробки
- Маршрутизация по файлам и вложенные раскладки.
- Рендеринг на сервере и генерация статических страниц.
- Оптимизация изображений и шрифтов.
- Серверные маршруты для [[API]] внутри одного проекта.
- Работа с TypeScript без дополнительной настройки.

### Чем отличается от React
React — библиотека для интерфейса. Next.js — фреймворк, в котором React уже встроен вместе с маршрутизацией, сборкой и серверной частью. Если нужен сайт для поиска и клиентов, Next.js экономит недели настройки.

### Типичные ошибки
- Весь сайт рендерится в браузере, и SEO-преимущество пропадает.
- Тяжёлые клиентские библиотеки раздувают бандл и портят Core Web Vitals.
- Не настроены мета-теги и канонические адреса для каждой страницы.
- Хостинг подбирают без учёта серверных функций, а потом сайт не запускается.

### Частый вопрос
**Подходит ли Next.js для сайта в России?** Да. Фреймворк свободный, и сайт можно запускать на любом сервере с Node.js, в том числе на российском хостинге или в контейнере. Vercel нужен не обязательно, но некоторые функции удобнее работают на нём, поэтому хостинг стоит выбирать заранее.
