# OAuth

**Категория:** [[Глоссарий — Веб-разработка]]
**URL:** nikalimp.ru/glossary/oauth

## Определение

OAuth — это открытый протокол, который позволяет приложению получить ограниченный доступ к данным пользователя в другом сервисе, не зная его пароля. Сейчас используется версия OAuth 2.0.

Протокол работает через выдачу [[Токен|токенов]]. Когда вы нажимаете «Войти через Яндекс» или «Войти через VK ID», сайт перенаправляет вас на страницу сервиса. Там вы вводите пароль, сервис показывает, какие права просит приложение, и вы соглашаетесь. После этого сайт получает токен доступа с ограниченными правами и сроком жизни. Пароль остаётся только у сервиса.

Важно не путать OAuth с входом как таковым. OAuth отвечает на вопрос «что приложению разрешено делать», а не «кто этот человек». Для входа поверх него строят надстройку OpenID Connect, которая добавляет данные об идентификации пользователя.

Токены в OAuth живут недолго. Обычно выдают короткоживущий токен доступа и более долгий токен обновления, с помощью которого получают новый доступ без повторного входа пользователя. Если токен украден, ущерб ограничен его правами и сроком. Именно поэтому OAuth безопаснее, чем передача пароля сторонней программе.

### Как проходит вход (упрощённо)
1. Пользователь нажимает «Войти через сервис» на сайте.
2. Сайт перенаправляет его на страницу сервиса с указанием, какие права нужны.
3. Пользователь входит в сервис и подтверждает доступ.
4. Сервис возвращает на сайт одноразовый код.
5. Сайт обменивает код на токен доступа на своём сервере.
6. По токену сайт запрашивает разрешённые данные, например имя и почту.

### Зачем это нужно
- Пользователю не нужно придумывать новый пароль и запоминать его.
- Сайт не хранит пароли и не отвечает за их утечку.
- Права можно ограничить: только чтение почты или только имя.
- Доступ можно отозвать в настройках сервиса без смены пароля.

### Типичные ошибки
- Токен хранят в открытом виде там, где его может прочитать чужой скрипт.
- Запрашивают больше прав, чем нужно, и пользователи отказываются.
- Не проверяют параметр `state` и открывают дорогу подделке запросов.
- Секрет приложения лежит в коде страницы, а не на сервере.

### Частый вопрос
**Чем OAuth отличается от обычной авторизации по паролю?** При обычной схеме сайт сам проверяет ваш пароль. При OAuth проверку делает сторонний сервис, а сайт получает токен с заданными правами. Сайту не нужно хранить пароли, а вам не нужна ещё одна учётная запись. Подробнее о самой проверке прав читайте в статье про [[Авторизация|авторизацию]].
