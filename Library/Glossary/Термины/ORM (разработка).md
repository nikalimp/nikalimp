# ORM (разработка)

**English:** Object-Relational Mapping
**Категория:** [[Глоссарий — Веб-разработка]]
**URL:** nikalimp.ru/glossary/object-relational-mapping

## Определение

ORM (Object-Relational Mapping, объектно-реляционное отображение) — это прослойка в коде приложения, которая связывает таблицы [[База данных|базы данных]] с объектами языка программирования. Вместо SQL-запросов разработчик работает с привычными классами и методами.

Без ORM код обращается к базе строками на языке [[SQL]]: `SELECT * FROM users WHERE id = 5`. С ORM то же выглядит как вызов функции, например `User.find(5)`. Библиотека сама строит запрос, отправляет его в базу и превращает строки результата в объекты. Такая модель экономит время и делает код читаемым.

ORM есть почти у каждого языка и фреймворка: Django ORM и SQLAlchemy в Python, Eloquent в PHP (Laravel), Hibernate в Java, Prisma и Drizzle в экосистеме [[TypeScript (термин)|TypeScript]] и [[Node.js (термин)|Node.js]]. Они поддерживают разные СУБД: [[PostgreSQL (термин)|PostgreSQL]], MySQL и другие.

ORM появился потому, что объекты в коде и таблицы в базе устроены по-разному, и переводить одно в другое вручную утомительно. Эту проблему разработчики называют объектно-реляционным несоответствием. ORM скрывает неудобства, но не отменяет необходимости понимать, как работает база: производительность запросов всё равно зависит от структуры данных и индексов.

### Что умеет ORM
- Описывать структуру таблиц в виде моделей в коде.
- Выполнять запросы: выборка, добавление, изменение, удаление.
- Строить связи: у клиента много заказов, у заказа много товаров.
- Управлять миграциями: изменять схему базы по истории версий.
- Подстраиваться под другую СУБД почти без правки кода.

### Чем отличается от SQL
SQL — язык запросов к базе, ORM — инструмент, который пишет эти запросы за вас. На простых операциях ORM удобнее. На сложных отчётах с многими соединениями и подзапросами SQL нередко понятнее и быстрее, и многие ORM позволяют вставлять сырой SQL.

### Типичные ошибки
- Проблема N+1: код делает по отдельному запросу на каждую строку списка, и страница тормозит.
- Выгружают из базы все поля, когда нужны два.
- Не смотрят, какой SQL генерирует ORM.
- Слепо доверяют автоматическим миграциям на рабочей базе без резервной копии.

### Частый вопрос
**Обязательно ли использовать ORM?** Нет. Для небольших проектов и сложной аналитики можно обойтись чистым SQL или лёгкими построителями запросов. ORM особенно полезен в проектах с множеством связанных сущностей и командой, где важна единая структура кода.
