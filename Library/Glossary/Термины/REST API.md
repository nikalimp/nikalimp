# REST API

**Категория:** [[Глоссарий — Веб-разработка]]
**URL:** nikalimp.ru/glossary/rest-api

## Определение

REST API — это способ организации [[API]], при котором приложения обмениваются данными по протоколу HTTP, а каждый объект (товар, заказ, пользователь) доступен по собственному адресу. REST расшифровывается как Representational State Transfer.

Принципы REST описал Рой Филдинг в докторской диссертации в 2000 году. На практике это набор простых правил. У каждого ресурса свой адрес, например `/api/products/42`. Действие определяет HTTP-метод: GET — получить, POST — создать, PUT или PATCH — изменить, DELETE — удалить. Ответ приходит обычно в формате [[JSON]], а код ответа сообщает результат: 200 — успех, 404 — не найдено, 500 — ошибка сервера. Каждый запрос самостоятельный, сервер не хранит состояние между обращениями.

REST популярен из-за простоты: его понимают все языки и инструменты, а проверить запрос можно прямо из браузера или командной строки. Он лежит в основе большинства публичных интерфейсов сервисов — платёжных систем, мессенджеров, CRM.

Для маркетолога REST API важен как «розетка» сервиса. Через него CRM получает заявки с сайта, платёжная система сообщает об оплате, аналитика выгружает данные в отчёты. Чтобы подключить такой интерфейс, нужны адрес, ключ доступа и документация, где описаны допустимые запросы и форматы ответов.

### Пример
Запрос `GET /api/products/42` возвращает карточку товара с номером 42: название, цену и наличие. Запрос `POST /api/orders` с данными заказа создаёт новый заказ, а сервер отвечает кодом 201 и номером созданного заказа.

### Чем отличается от GraphQL
В REST у каждого ресурса свой адрес, и сервер сам решает, какие поля вернуть. В [[GraphQL]] есть единая точка входа, и клиент в запросе перечисляет нужные поля. REST проще и лучше кэшируется, GraphQL удобен, когда разным экранам нужны разные наборы данных.

### Типичные ошибки
- Глаголы в адресах: `/getProduct` вместо `GET /products`.
- Всегда возвращают код 200, даже при ошибке.
- Нет авторизации и ограничения частоты запросов.
- Меняют формат ответа без версии, и клиентские приложения ломаются.

### Частый вопрос
**Чем REST API отличается от обычного API?** API — общее понятие: любой способ, которым одна программа обращается к другой. REST API — конкретный стиль такого интерфейса поверх HTTP. Есть и другие стили, например GraphQL и gRPC, а также интерфейсы в виде [[Webhook|вебхуков]].
