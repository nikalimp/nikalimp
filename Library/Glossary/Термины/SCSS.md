# SCSS

**Категория:** [[Глоссарий — Веб-разработка]]
**URL:** nikalimp.ru/glossary/scss

## Определение

SCSS — это синтаксис препроцессора Sass, который расширяет обычный [[CSS]]: добавляет переменные, вложенность, миксины и вычисления, а затем компилируется в стандартный CSS для браузера.

SCSS появился как более удобная версия Sass. Старый синтаксис Sass обходился без фигурных скобок и точек с запятой, а SCSS полностью совместим с CSS: любой корректный CSS-файл уже является корректным SCSS. Поэтому перейти на него можно постепенно, переименовав файл и добавляя новые возможности по мере необходимости.

Браузеры SCSS не понимают. Перед публикацией сборщик переводит файлы `.scss` в обычные `.css`. Эту работу делает [[Препроцессор|препроцессор]] в составе проекта: Vite, Webpack или Next.js.

На практике SCSS часто встречается в давно существующих проектах, темах WordPress и дизайн-системах. Если вы принимаете сайт от подрядчика, исходные стили лежат в файлах .scss, а на сервере находится уже собранный CSS. Править нужно исходники, иначе правки пропадут при следующей сборке.

### Что даёт SCSS
- Переменные: цвета, шрифты и отступы задаются один раз, например `$main-color: #1a73e8;`.
- Вложенность: правила для дочерних элементов пишутся внутри родительского.
- Миксины: многократно используемые блоки стилей с параметрами.
- Разделение кода на файлы и подключение через `@use`.
- Функции и операции: вычисления размеров и цветов.

### Пример
Вместо повторения `.card .title {…}` и `.card .text {…}` стили записываются вложенно: внутри блока `.card` лежат `.title` и `.text`. Код короче и логичнее, а на выходе получается обычный CSS.

### Чем отличается от CSS-переменных
[[CSS-переменные]] работают прямо в браузере: их можно менять на лету, например при переключении тёмной темы. Переменные SCSS существуют только на этапе сборки и в готовом CSS заменяются значениями. Поэтому для тем часто используют CSS-переменные, а SCSS оставляют для миксинов и структуры.

### Типичные ошибки
- Глубокая вложенность на 5 уровней и больше: селекторы получаются громоздкими.
- Использование старой директивы `@import` вместо современной `@use`.
- Дублирование значений вместо переменных.
- Подключают SCSS ради одной переменной, хотя хватило бы CSS-переменных.

### Частый вопрос
**Нужен ли SCSS в 2020-х, если CSS сам получил переменные и вложенность?** Для многих проектов уже нет. Современный CSS закрывает основные потребности, а Tailwind и компонентные стили вообще обходятся без SCSS. Но в крупных существующих проектах SCSS остаётся популярным.
