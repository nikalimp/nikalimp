# Spec coding

**English:** Spec-Driven Development
**Синонимы:** Spec-driven development, Разработка по спецификации
**Категория:** [[Глоссарий — Веб-разработка]]
**URL:** nikalimp.ru/glossary/spec-coding

## Определение

Spec coding (spec-driven development, разработка по спецификации) — подход к разработке с AI, при котором сначала пишется подробная спецификация: что делает продукт, какие у него требования, архитектура и критерии готовности, — а уже по ней AI-агент генерирует код.

Спецификация становится главным артефактом проекта: её проверяет и правит человек, а код считается производным от неё. Если что-то нужно изменить, сначала меняют спецификацию, затем перегенерируют или обновляют код.

Чем отличается от vibe coding:
- **вайб-кодинг** — быстрый диалог «сделай, поправь», план живёт в голове и в истории чата;
- **spec coding** — план, требования и задачи зафиксированы в файлах, поэтому результат предсказуемее, а проект проще передать другому человеку или агенту.

Подход в 2025 году популяризировали инструменты вроде GitHub Spec Kit и Amazon Kiro. На практике спецификацией служат Markdown-файлы с требованиями, планом и списком задач, а также файлы инструкций для агента вроде CLAUDE.md.

### Как устроена спецификация
Обычно это несколько Markdown-файлов:
1. **Требования** — что и для кого делаем, сценарии, ограничения, критерии приёмки.
2. **План** — архитектура, стек, структура данных, этапы.
3. **Задачи** — список шагов, которые агент выполняет по одному и отмечает готовыми.
4. **Правила** — стандарты проекта, которые нельзя нарушать: стиль кода, требования к SEO, доступности, безопасности.

### Плюсы и ограничения
Плюсы: результат воспроизводим, ошибки видны на этапе документа, а не кода, проект легко передать. Ограничения: на старте нужно больше времени, а спецификацию приходится поддерживать в актуальном состоянии. Для одноразовых прототипов это избыточно.

### Как NikAlimp использует spec coding
Каждый клиентский сайт начинается со спецификации: карта страниц, тексты, требования стандарта AI-ready сайта, критерии готовности. Агент собирает сайт по ней из стартового шаблона, а проверки запускаются автоматически. Подробнее — в описании [этапов работы](/#process) и статье [Vibe-coding мёртв. Что пришло на смену?](/blog/vibe-coding-is-dead/).
