## Определение

Supabase — это открытая платформа для бэкенда, которая даёт готовую базу данных [[PostgreSQL (термин)|PostgreSQL]], авторизацию, хранилище файлов и API в одном сервисе. Её часто называют открытой альтернативой Firebase.

Обычно для приложения нужно собрать несколько частей: базу, авторизацию пользователей, файлы, серверную логику. Supabase предоставляет их сразу. На основе таблиц Postgres платформа автоматически создаёт [[REST API]], и фронтенд получает данные без написания отдельного сервера. Есть вход по почте, паролю и через соцсети и сервисы по протоколу [[OAuth]], хранилище для изображений и документов, подписки на изменения данных в реальном времени и серверные функции (Edge Functions).

Доступ к данным регулируется правилами на уровне строк (Row Level Security, RLS): вы описываете в базе, какой пользователь что может видеть и менять. Это важно: без включённых правил данные могут оказаться открыты всем.

Платформа с открытым исходным кодом, поэтому её можно запустить на собственном сервере. Это удобно, если нужно хранить данные внутри страны, например по требованиям 152-ФЗ о персональных данных. В облачной версии данные находятся на серверах провайдера, поэтому юрисдикцию размещения стоит проверить заранее.

Платформа появилась в 2020 году как проект с открытым кодом и быстро набрала популярность среди разработчиков. Её сильная сторона — скорость старта: таблицу можно создать в браузере, и через минуту у вас уже есть готовый API. При росте проекта стоит продумать схему данных, права доступа и план миграций.

### Чем отличается от Firebase
[[Firebase (термин)|Firebase]] — продукт Google на основе документной базы. Supabase построен на реляционной Postgres и стандартном [[SQL]], а код открыт. Это упрощает переезд: данные можно выгрузить и перенести на любой другой сервер с Postgres.

### Кому и когда это нужно
- Стартапам и MVP, которым нужен быстрый бэкенд.
- Небольшим сервисам без выделенного бэкенд-разработчика.
- Проектам, где важно не привязываться к закрытой платформе.

### Типичные ошибки
- Не включают RLS и оставляют таблицы доступными по публичному ключу.
- Кладут секретный сервисный ключ в клиентский код.
- Используют облако для персональных данных россиян, не проверив требования закона.
- Не настраивают резервные копии.

### Частый вопрос
**Заменяет ли Supabase разработчика бэкенда?** Для простых задач да: CRUD, вход, файлы. Для сложной бизнес-логики, интеграций и высоких нагрузок бэкенд всё равно понадобится, но Supabase заметно сокращает объём работы на старте.
