# Task flow

**English:** Task Flow
**Категория:** [[Глоссарий — UI-UX дизайн]]
**URL:** nikalimp.ru/glossary/task-flow

## Определение

Task flow — это схема шагов, по которым человек выполняет одну конкретную задачу в продукте: от начала до результата. Например, «оформить заказ» или «сбросить пароль».

В отличие от [[User flow]], где показано множество возможных путей и входов в продукт, task flow описывает единственный сценарий и обычно не разветвляется на разные цели. Это линейная или почти линейная последовательность действий и экранов. Она показывает, сколько шагов нужно человеку и где могут возникнуть сложности.

Task flow рисуют блок-схемой: прямоугольники — экраны или действия, ромбы — решения («данные верны?»), стрелки — переходы. Схема помогает увидеть лишние шаги и договориться с командой о том, как задача должна работать, до того как начнётся рисование экранов.

### Пример
Задача «записаться на консультацию»:
1. Пользователь открывает страницу услуги.
2. Нажимает «Записаться».
3. Выбирает дату и время.
4. Вводит имя и телефон.
5. Принимает согласие на обработку персональных данных (152-ФЗ).
6. Видит страницу подтверждения.

Развилки: нет свободного времени — предложить другой день; ошибка в телефоне — показать подсказку и сохранить введённое.

### Как построить
1. Сформулируйте задачу с точки зрения пользователя и результат, который он хочет получить.
2. Определите стартовую точку: откуда человек приходит.
3. Выпишите шаги и убирайте всё, что не нужно для результата.
4. Добавьте решения и ошибочные ветки: что происходит, если данные неверные или действие невозможно.
5. Отметьте конечную точку.
6. Проверьте схему на 2–3 пользователях или коллегах: попросите пройти шаги по схеме вслух.

### Типичные ошибки
- Смешивать несколько задач на одной схеме.
- Рисовать только «счастливый путь» и забывать ошибки и пустые состояния.
- Добавлять шаги, которые нужны компании, но не нужны пользователю (лишние поля, обязательная регистрация).
- Описывать внутреннюю логику системы вместо действий человека.

### Чем отличается от user flow
User flow показывает путь человека по продукту с учётом разных входов и целей. Task flow — детализация одной задачи. Часто user flow собирают из нескольких task flow.

### Task flow и аналитика
Схема задачи помогает настроить аналитику: каждый шаг становится событием или целью в Яндекс Метрике. Затем по данным видно, на каком шаге пользователи уходят. Так схема превращается из рисунка в рабочий инструмент и показывает, какой именно шаг нужно упростить.

### Частый вопрос
**Сколько шагов должно быть в task flow?** Нет универсального числа: столько, сколько действительно нужно для результата. Но каждый шаг стоит проверять вопросом «что будет, если его убрать?». Если ничего не сломается, шаг лишний. Для частых задач вроде оформления заказа сокращение шагов обычно повышает долю завершивших.
