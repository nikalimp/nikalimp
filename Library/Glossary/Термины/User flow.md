# User flow

**English:** User Flow
**Категория:** [[Глоссарий — UI-UX дизайн]]
**URL:** nikalimp.ru/glossary/user-flow

## Определение

User flow (пользовательский поток) — это схема пути человека по продукту: какие экраны и действия он проходит, чтобы достичь цели, и какие решения принимает по дороге.

Схема показывает продукт глазами пользователя, а не структуры сайта. Здесь важно не «какие страницы существуют», а «как человек попадает от точки входа к результату». Например, от рекламы в Яндексе до оформленной заявки. Поток включает развилки: что происходит, если человек уже зарегистрирован, если ввёл неверные данные, если передумал.

User flow рисуют до дизайна экранов. Он помогает команде договориться о логике, увидеть лишние шаги и недостающие экраны, а разработчикам и аналитикам — понять, какие события отслеживать.

### Как построить
1. Выберите пользователя и цель: «новый посетитель хочет заказать расчёт стоимости».
2. Определите точку входа: поиск, реклама, письмо, прямой заход.
3. Выпишите шаги, которые нужны для цели. Убирайте всё лишнее.
4. Добавьте решения (ромбы) и альтернативные ветки.
5. Покажите ошибки и тупики и как из них выйти.
6. Отметьте финальный результат.
7. Проверьте схему с коллегами и несколькими людьми из аудитории.

### Пример
Цель: оформить заказ в магазине. Вход: карточка товара. Шаги: добавить в корзину, открыть корзину, ввести адрес, выбрать доставку, оплатить, увидеть подтверждение. Развилки: есть ли аккаунт (войти или продолжить как гость), подходит ли адрес для доставки, прошла ли оплата. По схеме видно, что регистрация без необходимости добавляет шаг, и от неё можно отказаться.

### Чем отличается от task flow
[[Task flow]] описывает выполнение одной задачи, а user flow охватывает путь человека от входа до цели и может включать несколько задач и источников входа. Ещё одно близкое понятие — [[CJM]]: карта пути клиента показывает эмоции, ожидания и точки контакта, включая офлайн, тогда как user flow описывает именно действия в продукте.

### Типичные ошибки
- Рисовать только идеальный сценарий.
- Описывать структуру сайта вместо действий человека.
- Делать слишком большую схему на все случаи сразу.
- Не обновлять схему после изменений продукта.
- Использовать её без проверки на реальных людях.

### Кому и когда это нужно
Схема пользовательского потока нужна при проектировании новых функций, перестройке воронки заявок и согласовании логики с разработчиками. Для маленького сайта достаточно набросать путь от входа до заявки на бумаге. Для сложного сервиса потоки делают для каждой важной роли отдельно.

### Частый вопрос
**Какой инструмент выбрать для user flow?** Подойдёт любой редактор схем: Figma и FigJam, Miro, Whimsical или даже бумага. Важнее содержание, чем инструмент. Выберите тот, что есть у всей команды и в котором схему удобно обсуждать и править.
