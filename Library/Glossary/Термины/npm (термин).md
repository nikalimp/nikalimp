## Определение

npm — это менеджер пакетов для JavaScript и одновременно крупнейший реестр открытых библиотек. С его помощью разработчик подключает к проекту чужой код одной командой, например `npm install react`.

Название расшифровывается как Node Package Manager. Программа устанавливается вместе с [[Node.js (термин)|Node.js]]. Каждый проект хранит список зависимостей в файле `package.json`, а точные версии — в `package-lock.json`. Благодаря этому другой разработчик или сервер сборки получает ровно те же версии пакетов, выполнив `npm install`.

Через npm ставят фреймворки ([[React (термин)|React]], [[Vue]]), утилиты ([[Tailwind CSS (термин)|Tailwind CSS]], [[TypeScript (термин)|TypeScript]]), а также запускают скрипты проекта: `npm run build` собирает сайт, `npm run dev` поднимает локальный сервер.

### Основные команды
1. `npm install` — установить всё из `package.json`.
2. `npm install имя-пакета` — добавить новый пакет.
3. `npm run имя-скрипта` — выполнить скрипт из `package.json`.
4. `npm update` — обновить пакеты в пределах разрешённых версий.
5. `npm audit` — проверить зависимости на известные уязвимости.

### Типичные ошибки
- Добавляют пакет ради одной мелкой функции и тащат за ним десятки зависимостей.
- Не фиксируют версии или удаляют `package-lock.json`, и сборка у разных людей отличается.
- Коммитят папку `node_modules` в репозиторий. Её не нужно хранить в [[Git]].
- Ставят пакеты по названию, не проверив автора и популярность: так распространяются вредоносные пакеты.

### Чем отличается от соседних инструментов
Yarn и pnpm решают ту же задачу и тоже берут пакеты из реестра npm. Они отличаются скоростью и способом хранения файлов. Для большинства проектов разница несущественна.

### Частый вопрос
**Нужно ли знать npm, чтобы сделать сайт?** Для сайта на конструкторе вроде Tilda — нет. Для разработки на современных фреймворках — да: без npm не установить зависимости и не запустить сборку.
