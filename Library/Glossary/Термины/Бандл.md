# Бандл

**English:** Bundle
**Категория:** [[Глоссарий — Веб-разработка]]
**URL:** nikalimp.ru/glossary/bundle

## Определение

Бандл (bundle, «пакет») — это итоговый файл или набор файлов, в которые сборщик объединяет весь код сайта и его зависимостей, чтобы отдать браузеру. Обычно это JavaScript-файлы, иногда вместе со стилями.

Во время разработки проект состоит из сотен маленьких модулей: ваши файлы и пакеты из [[npm (термин)|npm]]. Браузеру неудобно загружать их по отдельности. Сборщик (Vite, webpack, esbuild, Rollup) собирает модули в несколько файлов, сжимает их ([[Минификация|минификация]]), убирает неиспользуемое ([[Tree shaking|tree shaking]]) и добавляет к именам хеш для кэширования.

Размер бандла напрямую влияет на скорость: чем больше JavaScript, тем дольше его скачивать, разбирать и выполнять, особенно на слабых телефонах. Это отражается на метриках [[Core Web Vitals]] и на конверсии.

### Как уменьшить бандл
1. Посмотрите состав бандла анализатором и найдите самые тяжёлые пакеты.
2. Замените тяжёлые библиотеки лёгкими аналогами или нативными возможностями браузера.
3. Импортируйте только нужные функции, а не библиотеку целиком.
4. Разделите код по страницам и грузите его по требованию (code splitting).
5. Включите сжатие gzip или brotli на сервере.

### Типичные ошибки
- Подключают библиотеку ради одной функции.
- Грузят на каждой странице код, нужный только на одной.
- Оставляют в боевой сборке отладочный код и исходные карты.
- Никогда не смотрят размер, пока сайт не начинает тормозить.

### Чем отличается от соседних понятий
Бандл — результат сборки. [[Деплой]] — выкладка этого результата на сервер. Минификация — один из шагов получения бандла.

### Частый вопрос
**Какой размер бандла считается нормальным?** Универсальной цифры нет, она зависит от типа сайта. Ориентир такой: для лендинга и контентного сайта JavaScript должен быть минимальным, для сложного веб-приложения допустимо больше, но грузиться нужно постепенно. Лучше проверять реальную скорость в Lighthouse на среднем телефоне.
