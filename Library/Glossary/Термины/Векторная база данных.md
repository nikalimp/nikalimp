# Векторная база данных

**English:** Vector Database
**Категория:** [[Глоссарий — AI и LLM]]
**URL:** nikalimp.ru/glossary/vector-database

## Определение

Векторная база данных — это хранилище, которое держит тексты, картинки и другие данные в виде векторов (списков чисел, эмбеддингов) и быстро находит ближайшие по смыслу.

Обычная база ищет точное совпадение: нужное слово, номер, дату. Векторная база отвечает на другой вопрос: «что похоже на это?». Каждый документ сначала превращают в [[Эмбеддинг]] — набор из сотен или тысяч чисел, который отражает смысл текста. Похожие по смыслу тексты получают близкие векторы. Когда приходит запрос, его тоже превращают в вектор, а база возвращает записи с наименьшим расстоянием до него.

Перебирать миллионы векторов по одному слишком долго, поэтому такие базы строят специальные индексы для приближённого поиска ближайших соседей. Ответ получается чуть менее точным, зато приходит за миллисекунды. Вместе с вектором обычно хранят сам текст и метаданные: адрес страницы, дату, язык, автора.

### Зачем это нужно
Главный сценарий — [[RAG]]: перед ответом модель получает из базы несколько подходящих фрагментов ваших документов и отвечает уже с их учётом. Так чат-бот на сайте отвечает по вашим услугам и прайсу, а не выдумывает. Второй сценарий — [[Семантический поиск]] по сайту или базе знаний: человек пишет «как вернуть деньги», а находится статья «Условия возврата». Третий — рекомендации и поиск дублей.

### Как это устроено на практике
1. Текст режут на фрагменты (см. [[Чанкинг контента]]).
2. Каждый фрагмент превращают в вектор моделью эмбеддингов.
3. Векторы вместе с текстом и метаданными записывают в базу.
4. Запрос пользователя превращают в вектор той же моделью.
5. База возвращает ближайшие фрагменты, их передают языковой модели.

Важное правило: запрос и документы нужно кодировать одной и той же моделью. Если сменить модель, всю базу придётся пересчитать.

### Типичные ошибки
- Резать текст на слишком длинные или слишком короткие куски: смысл теряется.
- Не хранить метаданные, а потом не мочь отфильтровать результат по языку или дате.
- Не обновлять базу после правок на сайте, и ответы устаревают.
- Использовать векторную базу там, где хватит обычного поиска по словам.

### Кому и когда это нужно
Если у вас пара десятков страниц, отдельная векторная база не нужна: хватит обычного поиска или расширения для привычной СУБД. Она оправдана, когда документов тысячи и нужен умный поиск или бот с ответами по вашим материалам.

### Как выбрать
Смотрите на объём данных, скорость ответа и удобство эксплуатации. Для небольшого проекта хватит расширения к привычной СУБД, например для PostgreSQL. Для больших коллекций берут специализированные решения. Проверьте, поддерживает ли база фильтры по метаданным и гибридный поиск: на практике они нужны почти всегда.

### Частый вопрос
**Чем векторная база отличается от обычной?** Обычная база ищет по точным значениям и условиям, векторная — по близости смысла. На практике их часто совмещают: фильтруют по полям, а внутри отобранного ищут по смыслу.
