# Карта сайта (UX)

**English:** UX Sitemap
**Категория:** [[Глоссарий — UI-UX дизайн]]
**URL:** nikalimp.ru/glossary/ux-sitemap

## Определение

Карта сайта в UX (UX sitemap) — это схема, которая показывает все страницы сайта и связи между ними в виде дерева или блок-схемы. Она нужна проектировщикам, дизайнерам и заказчикам, чтобы заранее увидеть структуру, до рисования экранов.

Не путайте её с файлом sitemap.xml, который отправляют поисковым системам. UX-карта предназначена для людей: по ней обсуждают состав разделов, уровни вложенности и порядок страниц. Файл sitemap.xml — для роботов, он перечисляет адреса для индексации.

Типичная карта выглядит как иерархия: сверху главная, ниже основные разделы (услуги, о компании, блог, контакты), ещё ниже страницы внутри разделов. Стрелками или линиями показывают дополнительные связи, например переход из статьи в услугу. Часто карту дополняют пометками: тип страницы, наличие формы, шаблон, приоритет.

### Из чего состоит карта
- Узлы: страницы или группы страниц.
- Уровни: главная, разделы, подразделы, отдельные материалы.
- Связи: вложенность и перекрёстные ссылки.
- Пометки: шаблон страницы, источник контента, ответственный.
- Глобальные элементы: шапка, подвал и меню, которые есть на каждой странице.

### Как составить
1. Соберите список всех страниц и функций на основе целей сайта и задач аудитории.
2. Сгруппируйте по смыслу и выделите основные разделы. Основой служит [[Информационная архитектура|информационная архитектура]].
3. Расставьте уровни: самое важное ближе к главной.
4. Назовите страницы словами пользователей.
5. Отметьте шаблоны, чтобы понять, сколько уникальных макетов потребуется.
6. Покажите схему команде и заказчику, согласуйте, затем проверьте на людях.

### Инструменты
Карту рисуют в онлайн-досках и дизайн-редакторах, в таблицах или в специальных сервисах. Главное — чтобы схема была читаемой и её можно было быстро править.

### Типичные ошибки
- Слишком глубокая вложенность: сайт требует четырёх и больше кликов до нужной страницы.
- Дублирование страниц по разным разделам без причины.
- Карта отражает внутреннюю структуру компании, а не запросы людей.
- Нет шаблонов: после согласования выясняется, что страниц с уникальным дизайном вдвое больше.
- Карта не обновляется после изменений.

### Пример
Для сайта студии карта может выглядеть так: главная; услуги (разработка, дизайн, поддержка); кейсы; блог; о нас; контакты. Рядом с каждой услугой отмечено, что у неё есть страница с ценой и формой заявки. Уже на этом этапе видно, что нужно три шаблона страниц, а не двенадцать.

### Частый вопрос
**Нужна ли UX-карта небольшому сайту?** Да, даже для сайта из пяти страниц набросок структуры полезен. Он занимает полчаса и показывает, чего не хватает: например, страницы с ценами или ответами на вопросы. Для больших сайтов с сотнями страниц карта становится обязательным документом, без которого невозможно согласовать работу.
