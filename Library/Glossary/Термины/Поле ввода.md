# Поле ввода

**English:** Input Field
**Категория:** [[Глоссарий — UI-UX дизайн]]
**URL:** nikalimp.ru/glossary/input-field

## Определение

Поле ввода — это элемент интерфейса, в который пользователь вводит текст, числа или другие данные с клавиатуры: имя, email, телефон, комментарий. Это основа форм обратной связи, регистрации, оплаты и поиска.

Технически поле ввода — тег `<input>` с разными типами: text, email, tel, number, password, search, date. Правильный тип важен: на телефоне он открывает подходящую клавиатуру (цифровую для телефона, с символом «@» для email), а браузер помогает с автозаполнением и простой проверкой. Для многострочного текста используют `<textarea>`.

Хорошее поле ввода понятно без объяснений: у него есть [[Лейбл|лейбл]], достаточная ширина, чёткие границы, видимое состояние при фокусе и понятная реакция на ошибку. Это базовый элемент [[Форма|формы]], а качество форм напрямую влияет на [[Конверсия|конверсию]]: чем проще заполнить, тем больше людей дойдёт до конца.


Отдельное внимание стоит уделить специальным полям. Поле пароля должно позволять показать введённые символы и вставить значение из менеджера паролей. Поле телефона удобнее без жёсткой маски, которая мешает вставке. Поле поиска нужна кнопка очистки и понятная реакция на нажатие Enter. Такие мелочи заметно снижают раздражение при заполнении.
### Состояния поля ввода
- По умолчанию — пустое поле с границей.
- Наведение — лёгкая смена границы или фона.
- Фокус — заметная рамка или подсветка, чтобы было видно, где курсор.
- Заполнено — введённый текст контрастнее подсказки.
- Ошибка — красная граница, иконка и текст рядом с описанием проблемы.
- Успех — галочка, если нужна подтверждённая проверка.
- Неактивно — серый вид, поле нельзя изменить. Подробнее — про [[Состояния элемента|состояния элемента]].

### Как сделать удобное поле ввода
1. Подпишите его видимым лейблом и при необходимости добавьте [[Плейсхолдер|плейсхолдер]] с примером.
2. Выберите правильный тип и атрибут autocomplete, чтобы браузер подставлял данные.
3. Сделайте поле достаточно высоким для касания: около 44–48 пикселей на мобильном.
4. Проверяйте ввод аккуратно: показывайте ошибку после того, как человек закончил писать, а не на каждый символ.
5. Объясняйте ошибку по-человечески: «Введите телефон в формате +7 900 000-00-00».
6. Не просите лишнего: каждое лишнее поле снижает долю отправленных форм.

### Типичные ошибки
- Поле без лейбла или с подсказкой вместо лейбла.
- Принудительная маска, которая не пускает вставить номер в привычном виде.
- Ошибка появляется только вверху страницы, а не у поля.
- Мелкие поля, в которые трудно попасть пальцем.
- Нет видимого фокуса, и с клавиатуры непонятно, где пользователь.
- Ограничение длины, которое обрезает фамилии или адреса.

### Частый вопрос
**Сколько полей должно быть в форме заявки?** Чем меньше, тем лучше. Для первого контакта обычно хватает имени и способа связи, остальное можно уточнить позже. Каждое дополнительное поле уменьшает число заполненных форм, поэтому оставляйте только те, без которых нельзя ответить клиенту.
