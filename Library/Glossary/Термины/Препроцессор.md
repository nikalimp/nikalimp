# Препроцессор

**English:** CSS Preprocessor
**Категория:** [[Глоссарий — Веб-разработка]]
**URL:** nikalimp.ru/glossary/css-preprocessor

## Определение

Препроцессор CSS — это надстройка над CSS с расширенным синтаксисом: переменными, вложенностью, миксинами и функциями. Код на препроцессоре компилируется в обычный [[CSS]], который понимает браузер.

Браузеры не умеют читать файлы препроцессора, поэтому при сборке проекта специальная программа превращает их в стандартные стили. Самые известные препроцессоры — Sass (с синтаксисом [[SCSS]]), Less и Stylus. Они появились, когда в самом CSS не было переменных и удобной организации кода на больших проектах.

Сегодня многое из этого есть в чистом CSS: [[CSS-переменные]] (custom properties), вложенность, функции `calc()` и `clamp()`. Поэтому для небольших сайтов препроцессор часто не нужен. Но в старых и крупных кодовых базах Sass остаётся привычным инструментом.

Историческая причина появления препроцессоров проста: в CSS долго не было ни переменных, ни вложенности, ни удобного разделения на файлы. Разработчики вынуждены были копировать значения и писать длинные селекторы. Препроцессоры решили эти проблемы раньше, чем они попали в стандарт. Сегодня выбор зависит от проекта: для нового небольшого сайта часто хватает современного CSS, а в крупных системах дизайна и старых кодовых базах Sass по-прежнему остаётся рабочим инструментом, особенно вместе с готовыми библиотеками стилей. 

### Что даёт препроцессор
- Переменные для цветов, отступов и шрифтов, которые меняются в одном месте.
- Вложенность селекторов: стили блока записываются внутри него.
- Миксины — повторно используемые наборы свойств.
- Разбиение стилей на файлы и подключение через импорт.
- Циклы и условия для генерации однотипных классов.

### Пример
В SCSS можно записать `$accent: #1a73e8;` и вложить правила: `.card { padding: 16px; &:hover { color: $accent; } }`. После компиляции получатся два обычных правила: `.card` и `.card:hover`.

### Типичные ошибки
- Глубокая вложенность на 5–6 уровней: селекторы получаются громоздкими и их трудно переопределять.
- Подключают препроцессор там, где хватило бы CSS-переменных.
- Миксины с копированием кода раздувают итоговый файл.
- Забывают про сборку: файл `.scss` нельзя положить на сайт как есть.

### Чем отличается от CSS-переменных
Переменные препроцессора существуют только во время компиляции и в готовом CSS исчезают. CSS-переменные живут в браузере, их можно менять скриптом и переопределять в разных темах, например для [[Тёмная тема]].

### Частый вопрос
**Нужен ли Sass в 2026 году?** Не всегда. Для нового небольшого проекта хватает современного CSS с переменными и вложенностью. Sass оправдан, если вы поддерживаете большую систему стилей на нём или команде нужны миксины и циклы.
