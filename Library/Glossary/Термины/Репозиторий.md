# Репозиторий

**English:** Repository
**Категория:** [[Глоссарий — Веб-разработка]]
**URL:** nikalimp.ru/glossary/repository

## Определение

Репозиторий — это хранилище проекта, в котором лежат файлы кода и вся история их изменений. Чаще всего репозиторий ведут в системе контроля версий [[Git]].

В отличие от обычной папки, репозиторий помнит каждое изменение: кто, когда и что поменял, и позволяет вернуться к любой прошлой версии. Репозиторий бывает локальным (на вашем компьютере) и удалённым — на сервисе вроде [[GitHub (термин)]] или GitLab. Удалённый репозиторий нужен, чтобы работать командой, хранить резервную копию и запускать автоматическую выкладку сайта.

Для сайтов репозиторий часто служит источником правды: изменения попадают в него, а оттуда автоматически уходят на хостинг ([[CI-CD]]). Так [[Vercel (термин)]] и [[Netlify (термин)]] публикуют сайт после каждого [[Коммит]] в основную ветку.

Репозитории бывают публичными и приватными. Публичный виден всем и подходит для открытых проектов и портфолио, приватный доступен только приглашённым людям и используется для клиентских и коммерческих проектов. Для заказчика репозиторий — гарантия: код не заперт у одного исполнителя, а при смене подрядчика новый специалист видит историю и продолжает работу. Поэтому при заказе разработки стоит просить, чтобы репозиторий был создан на вашем аккаунте или передан вам по окончании работ. Хранить в репозитории стоит и документацию: короткий файл README с описанием, как запустить проект, сэкономит часы тому, кто будет продолжать работу.

### Из чего состоит
- Файлы проекта: код, стили, изображения.
- История коммитов — снимков состояния проекта.
- [[Ветка]] для параллельной работы над разными задачами.
- Служебные файлы: README с описанием, `.gitignore` со списком того, что не нужно хранить.

### Как начать
1. Установите Git и создайте репозиторий командой `git init` в папке проекта.
2. Добавьте файлы и сохраните первый коммит.
3. Создайте пустой репозиторий на GitHub и свяжите его с локальным.
4. Отправьте код на сервис.
5. Дальше работайте через ветки и [[Pull request]].

### Типичные ошибки
- Кладут в репозиторий пароли и ключи доступа. Их нельзя хранить в коде, для этого есть [[Переменные окружения]].
- Коммитят тяжёлые файлы и папки сборки.
- Работают только в основной ветке без проверки.
- Не пишут понятные комментарии к коммитам.

### Частый вопрос
**Нужен ли репозиторий для небольшого сайта?** Да, даже для сайта-визитки. Он даёт историю изменений, резервную копию и возможность откатить правку. Для сайтов на конструкторе его заменяет встроенная история версий.
