# Состояния элемента

**English:** UI States
**Категория:** [[Глоссарий — UI-UX дизайн]]
**URL:** nikalimp.ru/glossary/ui-states

## Определение

Состояния элемента (UI states) — это набор внешних видов, которые принимает один и тот же компонент интерфейса в зависимости от действий пользователя и состояния системы: обычное, наведение, фокус, нажатие, недоступное, загрузка, ошибка.

Любой интерактивный элемент должен «отвечать» человеку. Кнопка при наведении слегка меняет цвет, при нажатии вдавливается, при загрузке показывает [[Лоадер|индикатор]], а когда действие недоступно, выглядит приглушённой. Такая обратная связь подтверждает, что интерфейс заметил действие, и подсказывает, что делать дальше. Это прямое следствие принципа видимости состояния системы из [[Эвристики Нильсена|эвристик Нильсена]].

Состояния проектируют для каждого компонента отдельно и фиксируют в [[UI-кит|UI-ките]] или [[Дизайн-система|дизайн-системе]]. В Figma их оформляют как [[Вариант компонента|варианты компонента]], чтобы разработчик получил полный набор видов, а не только красивый «обычный» вариант.

### Основные состояния
- Default — исходный вид без взаимодействия.
- [[Hover]] — курсор над элементом. На сенсорных экранах этого состояния нет.
- [[Focus]] — элемент выбран с клавиатуры или кликом; нужен заметный контур.
- Active (pressed) — момент нажатия.
- [[Disabled]] — действие сейчас недоступно.
- Loading — идёт запрос, повторное нажатие блокируется.
- Error и Success — результат проверки или операции, например в [[Поле ввода|поле ввода]].
- Selected — элемент выбран, например пункт меню или [[Чекбокс|чекбокс]].

### Пример
Кнопка «Отправить заявку» в форме. По умолчанию она синяя. При наведении темнеет. Пока форма не заполнена, она серая и недоступна. После нажатия внутри появляется спиннер, а текст меняется на «Отправляем». Если сервер вернул ошибку, под кнопкой появляется сообщение, а сама кнопка снова активна.

### Как проверить, что состояния продуманы
1. Составьте таблицу: по строкам компоненты, по столбцам состояния.
2. Пройдите форму только с клавиатуры и убедитесь, что фокус всегда виден.
3. Отключите сеть и проверьте, как ведёт себя интерфейс при ошибке.
4. Откройте экран без данных и посмотрите на [[Пустое состояние]].
5. Проверьте контраст каждого состояния, включая недоступное, по [[WCAG]].

### Типичные ошибки
- Нарисован только «обычный» вид, остальное придумывает разработчик.
- Состояние фокуса убрано ради аккуратного вида.
- Состояние ошибки показано только цветом.
- Недоступная кнопка без объяснения причины.
- Нет состояния загрузки, и пользователь нажимает кнопку трижды.

### Кому и когда это нужно
Полный набор состояний нужен дизайнерам и разработчикам любого интерфейса: от лендинга с формой до сложной админки. Чем раньше состояния описаны в макете, тем меньше споров на передаче в разработку и тем реже на продакшене всплывают «забытые» случаи вроде ошибки сети или пустого списка.

### Частый вопрос
**Сколько состояний нужно описать для кнопки?** Минимум пять: обычное, наведение, фокус, нажатие и недоступное. Если кнопка запускает долгое действие, добавьте загрузку. Для сложных форм добавьте ошибку и успех.
