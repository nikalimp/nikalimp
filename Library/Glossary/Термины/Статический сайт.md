# Статический сайт

**English:** Static Website
**Категория:** [[Глоссарий — Веб-разработка]]
**URL:** nikalimp.ru/glossary/static-website

## Определение

Статический сайт — это сайт, страницы которого заранее собраны в готовые файлы HTML и отдаются посетителю без обращения к базе данных и без построения страницы на сервере в момент запроса.

Для динамического сайта (например, на [[WordPress (термин)]]) сервер при каждом запросе собирает страницу из шаблона и данных в базе. Статический сайт устроен проще: страницы создают один раз при сборке, и сервер просто отдаёт готовый файл. Такой подход называют [[SSG]] (генерацией статического сайта). Для сборки используют [[Next.js (термин)]], [[Astro (термин)]] и другие инструменты, а в связке с [[Headless CMS]] редакторы по-прежнему управляют содержимым в удобной админке. Подход описывает архитектура [[JAMstack]].

Термин «статический» не значит, что страница неподвижна или без анимаций. Скрипты в браузере по-прежнему могут делать интерфейс живым: меню, слайдеры, фильтры. «Статический» говорит только о том, что HTML-файлы готовы заранее. Для современных проектов часто используют гибридный подход: часть страниц собирается заранее, часть обновляется по расписанию ([[ISR]]), а динамические участки загружаются отдельно. Так можно сохранить скорость статики и при этом показывать актуальные данные. 

### Плюсы и ограничения
- Очень высокая скорость: файлы можно раздавать через [[CDN]].
- Безопаснее: нет базы и серверного кода, которые можно взломать.
- Дешёвый хостинг, часто бесплатный, и просто масштабировать.
- Минус: изменения видны только после новой сборки.
- Минус: пользовательские функции (поиск, формы, оплата) решаются через внешние сервисы или [[API]].

### Чем отличается от динамического сайта
Динамический сайт строит страницу «на лету» и подходит там, где содержимое меняется каждую секунду или зависит от пользователя: личные кабинеты, соцсети, магазины с остатками в реальном времени. Статический подходит там, где содержимое меняется редко: лендинги, блоги, документация, [[Сайт-визитка]].

### Как выбрать
1. Определите, как часто меняется содержимое.
2. Проверьте, нужны ли пользовательские данные на каждой странице.
3. Если нет — выбирайте статический сайт.
4. Если нужно чуть больше — комбинируйте: статика плюс [[Serverless]]-функции для форм.

### Типичные ошибки
- Выбирают статику для проекта с постоянно меняющимися данными.
- Забывают настроить автоматическую сборку после правок.
- Не продумывают, где будут храниться заявки из форм.

### Частый вопрос
**Подходит ли статический сайт для SEO?** Да, он считается одним из лучших вариантов: страницы быстро открываются, а поисковые роботы получают готовый HTML с содержимым, без ожидания скриптов.
