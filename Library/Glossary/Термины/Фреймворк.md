# Фреймворк

**English:** Framework
**Категория:** [[Глоссарий — Веб-разработка]]
**URL:** nikalimp.ru/glossary/framework

## Определение

Фреймворк — это готовый каркас для разработки: набор кода, правил и инструментов, на основе которого пишут проект, вместо того чтобы строить всё с нуля.

Фреймворк задаёт структуру приложения и берёт на себя типовые задачи: маршрутизацию, работу с данными, сборку, безопасность. Разработчик пишет только логику своего проекта. Главное отличие от библиотеки: библиотеку вы вызываете сами, когда нужно, а фреймворк управляет ходом программы и вызывает ваш код по своим правилам.

Фреймворки есть для разных задач. Для интерфейсов — [[React (термин)]], [[Vue]], [[Angular (термин)]], [[Svelte (термин)]]. Для сайтов на их основе — [[Next.js (термин)]], [[Nuxt (термин)]], [[Astro (термин)]]. Для сервера — Django, Laravel, Express. Для стилей — [[Tailwind CSS (термин)]] и Bootstrap.

Выбор фреймворка — это выбор экосистемы на годы вперёд. Вместе с ним вы получаете подход к архитектуре, набор готовых модулей и сообщество, которое отвечает на вопросы. С другой стороны, вы привязываетесь к его правилам: когда фреймворк сильно обновляется, проект нужно переносить на новую версию. Поэтому для долгих проектов выбирают зрелые и широко используемые решения, а для экспериментов и коротких кампаний можно брать то, что быстрее всего даёт результат. 

### Зачем нужен
- Ускоряет разработку: типовые вещи уже сделаны.
- Даёт единую структуру, и новым людям легче войти в проект.
- Содержит проверенные решения по безопасности и производительности.
- Есть сообщество, документация и готовые расширения.

### Чем отличается от библиотеки
Библиотека решает узкую задачу (например, работа с датами) и подключается там, где нужна. Фреймворк определяет архитектуру всего проекта, и менять его позже сложно.

### Как выбрать
1. Определите тип проекта: сайт с контентом, веб-сервис, магазин.
2. Оцените сложность: для простого лендинга фреймворк может быть избыточным.
3. Учтите, какие технологии знает команда.
4. Проверьте, что фреймворк активно развивается и у него есть документация.
5. Подумайте о SEO и скорости: подходит ли серверная отрисовка ([[SSR]], [[SSG]]).

### Типичные ошибки
- Берут модный фреймворк, не понимая, зачем он нужен проекту.
- Используют тяжёлый фреймворк для сайта в пять страниц.
- Не обновляют версии, и проект «застревает» на устаревшей.

### Частый вопрос
**Нужен ли фреймворк для сайта?** Для простой визитки — нет, хватит HTML, CSS и конструктора. Для сайта со сложной логикой, большим числом страниц и командой разработки — да, он сэкономит время и сделает код единообразным.
