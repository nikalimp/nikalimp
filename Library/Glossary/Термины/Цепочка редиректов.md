# Цепочка редиректов

**English:** Redirect Chain
**Категория:** [[Глоссарий — SEO]]
**URL:** nikalimp.ru/glossary/redirect-chain

## Определение

Цепочка редиректов — это ситуация, когда адрес A перенаправляет на B, B на C, и пользователь с роботом доходят до итоговой страницы только через несколько переходов вместо одного.

Цепочки появляются сами собой. Сайт сменил протокол с http на https, потом добавили www, потом поменяли структуру URL, и каждый раз новый редирект ставили поверх старого. Старый адрес теперь ведёт на промежуточный, а тот на актуальный.

Чем это плохо. Каждый переход добавляет задержку, и страница открывается медленнее. Поисковый робот тратит на лишние запросы [[Краулинговый бюджет]]. Если цепочка длинная, робот может не дойти до конца и оставить в индексе не тот адрес. Часть ссылочного веса теряется или передаётся дольше. Особенно опасны циклы, когда A ведёт на B, а B обратно на A: страница вообще не откроется.

### Пример
`http://site.ru/old` → `https://site.ru/old` → `https://www.site.ru/old` → `https://www.site.ru/new`. Три перехода, хотя достаточно одного: сразу на `https://www.site.ru/new`.

### Как найти и убрать цепочки
1. Просканируйте сайт краулером (например, Screaming Frog) и откройте отчёт по редиректам.
2. Отдельно проверьте старые адреса из внешних ссылок и из карты сайта.
3. Для каждой цепочки определите итоговый адрес.
4. Перенастройте первый редирект так, чтобы он вёл сразу на итоговую страницу.
5. Обновите внутренние ссылки, чтобы они вели прямо на актуальные URL, и поправьте sitemap.xml.
6. Проверьте результат повторным сканированием.

### Типичные ошибки
- Исправить только последний редирект и оставить промежуточные.
- Использовать 302 там, где нужен постоянный [[301 редирект]].
- Оставить внутренние ссылки на старые адреса.
- Ставить редирект на главную вместо релевантной страницы.

### Откуда берутся цепочки
Чаще всего цепочки возникают при переезде с http на https, смене домена, смене CMS и перестройке структуры. Каждый раз команда добавляет новый редирект, а старые не пересматривает. Хороший приём: перед каждой миграцией составить таблицу «старый адрес — итоговый адрес» и ставить редиректы сразу на итоговые страницы.

### Частый вопрос
**Сколько редиректов допустимо в цепочке?** Идеально один. Яндекс и Google проходят по нескольким переходам, но каждый лишний замедляет страницу и создаёт риск потерь, поэтому цепочки лучше схлопывать до одного шага.
