Плагин Git и GitHub PR даёт ИИ-агенту безопасный рабочий процесс с репозиторием: каждая задача делается в отдельной ветке `claude/<задача>`, проверяется через Pull Request и только после прохождения тестов попадает в `main`.

## Зачем нужен этот плагин

Прямые коммиты агента в главную ветку опасны: случайная ошибка сразу уходит на живой сайт, а откатывать её приходится вручную. Связка Git + `gh` CLI фиксирует историю каждого изменения, показывает понятный diff и связывает работу агента с проверками GitHub Actions.

## Инструкция по установке

1. Установите официальный **GitHub CLI** на macOS или Linux:

```bash
brew install gh
```

2. Авторизуйтесь в своём аккаунте GitHub (выберите HTTPS или SSH):

```bash
gh auth login
```

3. Проверьте доступ к репозиторию и статус открытых PR:

```bash
gh pr list
```

4. Зафиксируйте в `AGENTS.md` правило веток: правки кода агент коммитит в `claude/<задача>` и открывает PR командой `gh pr create`, а не пушит напрямую в `main`.

## Как проверить, что всё работает

Попросите агента посмотреть статус ветки и открытых Pull Request. Агент выполнит `git status` и `gh pr status` и вернёт список активных веток и статусы проверок CI.

## Частые ошибки

- Забывают переключиться от старой ветки и начинают новую задачу поверх уже слитого коммита вместо `origin/main`.
- Добавляют в коммит временные файлы, `.env` или локальные конфиги вместо точечного `git add`.
- Создают гигантский PR на десятки несвязанных задач, который невозможно проверить.

## Частые вопросы

### Зачем агенту отдельный GitHub CLI, если есть обычный git?

Обычный `git` умеет только коммитить и пушить ветки. Утилита `gh` позволяет агенту самому создавать Pull Request с описанием изменений, проверять логи GitHub Actions и видеть комментарии ревью.

### Нужен ли отдельный токен для gh CLI?

Команда `gh auth login` сама открывает авторизацию через браузер и безопасно сохраняет токен в системном хранилище ключей (macOS Keychain).

### Можно ли использовать worktree для параллельной работы агентов?

Да. `git worktree` позволяет запускать несколько агентов над разными задачами одновременно в изолированных папках одного репозитория без конфликтов файлов.
