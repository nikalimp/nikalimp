Spec Coding — это система файлов и правил для ИИ-агента, которая запрещает писать код без утверждённой спецификации. Вместо десятка противоречивых промптов агент работает по единому пакету документов в папке `specs/`.

## Зачем нужен этот плагин

При обычном «вайб-кодинге» нейросеть угадывает требования, придумывает лишние экраны и ломает архитектуру при каждой новой правке. Spec Coding переводит разработку на инженерные рельсы: сначала бриф и исследование, потом карта страниц и дизайн-токены, затем декомпозиция на конкретные задачи и только после этого — код.

## Что входит в комплект

- `specs/00-brief.md` — цели бизнеса, аудитория, регион, ограничения и KPI.
- `specs/01-research.md` — разбор конкурентов, семантики и пробелов рынка.
- `specs/02-spec.md` — карта страниц, URL, роли, формы, исключения и приёмочные критерии.
- `specs/03-design.md` — визуальная концепция, палитра, шрифты и бюджет анимаций.
- `specs/05-tasks.md` — атомарные задачи с проверяемым результатом.
- `specs/STATUS.md` — текущий этап проекта и список долгов.

## Инструкция по установке

1. Создайте в корне репозитория папку `specs/` и базовые шаблоны документов:

```bash
mkdir -p specs
touch specs/00-brief.md specs/01-research.md specs/02-spec.md specs/03-design.md specs/05-tasks.md specs/STATUS.md
```

2. Добавьте в файл инструкций агента (`AGENTS.md` или `CLAUDE.md`) жёсткое правило:

```markdown
## Перед началом работы
1. Прочитай `specs/STATUS.md` и `specs/02-spec.md`.
2. Не пиши код новых разделов без фиксации требований в спецификации.
3. После завершения задачи обновляй статус в `specs/STATUS.md`.
```

3. Запустите первую сессию с агентом и попросите заполнить `00-brief.md` вопросами к заказчику, а затем провести жёсткую проверку всех развилок до утверждения `02-spec.md`.

## Как проверить, что всё работает

Попросите ИИ-агента добавить новую страницу на сайт. Если правила подключены верно, агент сначала сверится с `specs/02-spec.md`, проверит формат URL, мета-теги и перелинковку, а не начнёт молча генерировать случайный макет.

## Частые ошибки

- Пишут спецификацию «для галочки» и забывают обновлять её после смены требований.
- Сваливают в один файл и бриф, и дизайн, и список багов — агент начинает путаться в длинном контексте.
- Оставляют в `02-spec.md` общие фразы вроде «сделать красиво и удобно» вместо проверяемых критериев.

## Частые вопросы

### Подходит ли Spec Coding для небольших лендингов?

Да. Для лендинга спецификация занимает 1–2 экрана текста, но спасает от забытых форм, политики ПДн, редиректов и слабых заголовков.

### Чем Spec Coding отличается от обычного ТЗ в Word?

Спецификация хранится в Markdown прямо рядом с кодом в Git. ИИ-агент читает её напрямую, а каждое изменение требований видно в истории коммитов.

### Нужно ли устанавливать отдельный npm-пакет?

Нет. Основа Spec Coding — структура Markdown-файлов и правила в `AGENTS.md`, поэтому она работает в любой среде: Claude Code, Cursor, Windsurf или BB.
