## Описание

Storybook — инструмент с открытым кодом для разработки и документирования UI-компонентов в изоляции. Каждый компонент — кнопка, карточка, модальное окно — показывается во всех состояниях отдельно от приложения.

Storybook стал стандартом для дизайн-систем на React, Vue, Angular и других фреймворках. Им пользуются крупные компании для документации компонентов.

### Возможности
- **Истории (stories)** — состояния компонента: обычное, наведение, ошибка, загрузка.
- **Controls** — изменение свойств компонента в интерфейсе.
- **Автодокументация** компонентов.
- **Тестирование:** взаимодействия, доступность, визуальная регрессия.
- **Аддоны** для темизации, адаптивности, макетов Figma.
- **Публикация** витрины компонентов.

### Кому подходит
Фронтенд-командам и дизайн-системщикам, которые поддерживают библиотеки компонентов. Продуктовым командам с несколькими приложениями на общей дизайн-системе.

### Как начать
Установите Storybook в проект командой инициализации, напишите истории для 3–5 базовых компонентов и опубликуйте витрину для дизайнеров.

### Как использовать в работе
Используйте Storybook на ревью дизайна: дизайнер видит реальные компоненты во всех состояниях и сравнивает с макетами Figma.

### Где особенно полезен
В дизайн-системах, где важно, чтобы компоненты одинаково работали во всех продуктах компании.

### Совет
Пишите истории для крайних случаев: длинный текст, пустые данные, ошибки. Именно они ломаются в продакшене.

### Ограничения
Поддержка Storybook требует времени разработчиков.

### Кому не подойдёт
Небольшим сайтам без собственной библиотеки компонентов.

### Связь с Figma
Аддон Designs показывает макет из Figma рядом с компонентом, и расхождения видно сразу.

### Частый вопрос
**Storybook или Zeplin?** [[Zeplin]] — для передачи макетов разработке, Storybook — для документации готовых компонентов в коде. Компоненты для React удобно брать из [[shadcn ui|shadcn/ui]].

## Вердикт
- Кому подходит: Фронтенд-разработчикам и дизайн-командам, которые ведут библиотеку компонентов.
- Кому не подходит: Небольшим сайтам из нескольких страниц, где нет повторяющихся компонентов.
- Итог: Storybook показывает компоненты интерфейса по отдельности и помогает проверять их, не запуская весь сайт.

## Плюсы

- Бесплатный и с открытым кодом

## Частые вопросы
### Storybook бесплатный?
Да, сам Storybook с открытым кодом и бесплатен. Платным бывает только облачный сервис Chromatic.

### Работает ли Storybook в России?
Да, он ставится в проект из npm и работает локально, без регистрации.

### Что лучше: Storybook или Figma?
Это разные задачи. [[Figma]] нужна для макетов, Storybook показывает готовые компоненты в коде. Их обычно используют вместе.

### Зачем нужен Storybook?
Он собирает каталог компонентов интерфейса, где их можно смотреть, тестировать и документировать отдельно от сайта.
